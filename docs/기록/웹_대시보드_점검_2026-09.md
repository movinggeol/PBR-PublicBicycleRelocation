# 웹 대시보드 점검 기록 (2026-09-21 ~ 09-22)

`webapp/`만 건드린 두 날의 점검 아홉 판(1.26.262~266, 1.26.271~273)이 **무엇을 왜 했는지**를
한 자리에 모았다. 판별 상세는 [버전관리.md](버전관리.md)의 각 절이 정본이고, 이 문서는 그 절들이
따로 말하지 않는 것 — 어떤 방법이 어떤 결함을 찾았는지, 고칠 때 무엇을 기준으로 삼았는지, 왜 어떤
것은 안 했는지, 만들며 걸린 함정 — 을 남긴다.

> 이 문서를 읽을 사람: 다음에 `webapp/`을 손대거나 같은 식의 점검을 다시 할 사람.
> 재현: `python tools/crawl_webapp.py` (실데이터 순회) · `python -m pytest tests/test_webapp.py`

## 2. 어떻게 찾았나 — 방법 다섯과 각자가 찾은 것

같은 코드를 다섯 방법으로 봤고, **방법마다 다른 결함이 나왔다.** 하나만 썼으면 나머지는 남았다.

| 방법 | 찾은 것 | 못 보는 것 |
| --- | --- | --- |
| **코드 읽기** (1.26.262) | 재고 대조의 '여유' 안내가 논리상 나올 수 없는 상태(`possible ≤ need`인데 `possible > need`를 찾음) · 실행 이름 무검사(`:`가 NTFS 대체 스트림) · `/orders?run_label=`만 주면 회차가 섞임 · 첫 화면 `int(nan)` | 실데이터에만 있는 값의 모양 |
| **실데이터 순회** (1.26.263 → `tools/crawl_webapp.py`) | cp949 원천 CSV 미리보기 500 · `duration=None` 링크 · 미리보기 `NaN` · 목록 도중 파일 삭제 | 화면이 "보이는가·동작하는가" |
| **브라우저 실행** (Playwright, 1.26.265·272) | 부분 갱신이 실제로 통째로 다시 그리지 않는지(창에 심은 표식으로 셌다) · 앵커가 고정 내비 뒤에 숨는 위치(8px) · 다크 명암비 2.82:1 | 계산의 옳음 |
| **실제 계획 돌리기** (1.26.266, 다섯 실행) | 중단한 작업의 한 단계가 계속 '진행 중'으로 깜박임 · 경과 시간 `1.0분`→`1분` 글자 흔들림 | 잠복 조건(NULL 회차 등) |
| **두 갈래 새 눈 감사** (1.26.271, 코드/템플릿 각각 다른 조사자) | 가중평균의 NULL 편향(0.5) · 종류 변경 라우트의 빈 라벨 생성 · 수집 기대 틱이 첫날 창 · 안내가 꺼진 이동시간 모형을 말함 · 정렬 단추 21개가 한 이름 | 조사자가 "추정"이라 표시한 것은 다시 재야 했다 |

**시험이 왜 못 봤나.** `tests/test_webapp.py`는 임시 DB로 돈다(`conftest.isolate_db`). 실데이터에만
있는 옛 산출물의 NULL, 실험 라벨, 좌표 없는 대여소, cp949 원천 파일은 시험이 만들지 않는 상태라
시험은 늘 통과했다. 1.26.263의 결함 둘과 1.26.271의 NaN 500 셋이 그렇게 잠복했다. 그래서 순회를
일회성 스크립트로 두지 않고 `tools/crawl_webapp.py`로 남겼다 — 다음 점검이 같은 것을 다시 쓸 자리다.
임시 DB에서 0건인지는 시험이 지키고, 실데이터에서 0건인지는 커밋 전에 손으로 돌린다.

**감사 결과를 그대로 믿지 않았다.** 6차의 두 조사 보고 중 핵심 주장 셋(가중평균·종류 라우트·405)은
커밋 전에 직접 재현했고, 조사가 "추정"이라 표시한 항목(이모지·`aria-current` 풍선)은 재지 않은 채로
고치지 않았다(4장).

## 4. 무엇을 기준으로 고쳤나 — 의도

고칠 때마다 되돌아간 기준들이다. 이 기준을 모르면 다음 수정이 이번 고침을 되돌릴 수 있다.

- **판정만 하고 계획을 바꾸지 않는다.** 거치대 수를 모르면 내려놓을 상한을 짐작해 "불가"라 하지 않고
  **"확인 불가"** 로 둔다(1.26.262). 자동 보정을 넣으면 기사가 든 종이와 화면이 어긋난다 — `pbr-pipeline`
  스킬의 규약이고, 이번 점검이 그 규약을 시험으로도 고정했다.
- **화면과 API는 같은 계산을 쓴다.** 진행 화면의 첫 그리기와 3초 뒤 갱신이 다른 계산이면 갱신되는 칸만
  슬며시 어긋난다 — `_run_view()` 하나(1.26.265). 첫 화면 헤드라인과 `/kpi`의 가중평균도 같은 이유로
  `kpi_view.weighted_mean` 하나(1.26.271). 끝난 작업의 단계 판정도 `_run_view()`에 두어 API가 같이
  바뀌게 했다(1.26.266).
- **스크립트는 서버가 가진 안내를 흉내 내지 않는다.** 부분 갱신은 돌고 있는 동안만 칸을 고치고, 끝나면
  한 번 통째로 다시 그린다. 완성·실패·중단 안내를 JS에도 적으면 두 곳이 갈린다(1.26.265).
- **기록이 없으면 숫자를 지어내지 않는다.** 예상 소요의 대체 문구 "보통 2~4분"·"2분 남짓"은 코드가 빨라지면
  거짓이 된다 — 1.26.214가 지운 것과 같은 부류라 걷었다(1.26.272). 첫 화면의 검정 문구도 낡은 n=15를
  README의 n=36으로 맞췄다.
- **설정은 코드에서 읽어 와 스위치를 따른다.** 안내의 이동시간 문장이 `USE_ROAD_MODEL`을 따르고 시험이
  양쪽을 다 본다(1.26.272). 한쪽 문장만 남기면 다음에 스위치를 끌 때 또 낡는다.
- **판정할 수 없으면 모른다고 한다.** 멈춤 판정(`_stalled_note`)은 날짜를 못 읽으면 `None`이고, 첫 화면의
  NULL 지표는 "출동 대수 기록 없음"이다(1.26.262). 짐작해서 "정상"이라 하면 알리려던 장치가 거짓말을 한다.
- **끝난 작업에 '진행 중'인 단계는 없다.** 로그에 `완료:`가 없어 running으로 남은 단계는 중단·실패·추적
  끊김이 **거기서** 멈춘 것이다 — `stopped`(■ · "여기서 멈춤")로 바꾼다(1.26.266).
- **내구성은 조건을 만들어 시험한다.** 비원자적 저장·중단 경쟁·저장 실패 뒤 훅은 실운영에서 재현되지
  않았지만, 조건이 오면 조용히 틀리는 부류라 시험이 조건(반쪽 파일·끝난 프로세스·`OSError`)을 만든다
  (1.26.273).
- **데이터를 지우는 결정은 사용자가 한다.** 실제 계획 다섯 건(`2026-09-21 16 웹점검*`)이 실 DB에 `plan`으로
  남아 첫 화면의 "마지막 계획"이 됐다. 실제 운영에 써도 되는 값이라 지우지 않고 남겼고, 지울지는 6장.

## 5. 만들며 걸린 함정 — 다음에 같은 자리에서 멈추지 않도록

- **시험이 상수를 잘못 가정했다.** 여유 안내 시험을 새로 쓰며 `TARGET_QTY_UPPER_RATIO = 1.2`로 짐작했는데
  실제는 1.5다. 시험은 상수를 import해 `ceiling = int(20 * TARGET_QTY_UPPER_RATIO)`로 세게 고쳤다. 1.26.262
  이전의 옛 시험도 계산이 만들 수 없는 상태(`possible > need`)를 손으로 만들어 통과시키고 있었다 —
  **시험 데이터는 계산이 실제로 낼 수 있는 값이어야 한다.**
- **`grep -v warnings`가 pytest 요약 줄을 삼켰다.** 요약에 "N warnings in"이 들어 있다. 요약은 `tail`로 본다.
- **셸 heredoc 안의 `\n`이 실제 줄바꿈으로 바뀌었다.** 파이썬 편집 스크립트를 heredoc으로 넘기면 문자열
  속 `\n`이 풀려 시험 파일이 두 번 깨졌다(`unterminated string literal`). 여러 줄 편집은 **스크립트를
  파일로 써서 실행**하거나 `Edit` 도구를 쓴다.
- **같은 작업 트리를 다른 세션이 쓰고 있었다.** `git status`에 논문 문서 열 개가 함께 떴고, TODO.md에는
  내 행과 남의 행이 한 hunk에 섞였다. 파일 이름으로 스테이징하는 것만으로는 못 가른다 — HEAD 내용에 내 줄만
  얹어 `git hash-object` → `git update-index --cacheinfo`로 인덱스에 올렸다(1.26.271 커밋). 커밋 뒤
  `git show --stat`으로 들어간 것을 확인하는 규약이 여기서 값을 했다.
- **테스트 개수 패처가 남의 파일을 건드린 줄 알았다.** 논문 문서의 큰 diff는 패처가 아니라 다른 세션의
  편집이었다. `git diff`에 `1002`가 더해진 줄이 있는지로 갈랐다. 판단 전에 diff를 봐야 한다.
- **`or 0`은 NaN을 참으로 본다.** `int(row.get("qty", 0) or 0)`은 NaN에서 `int(nan)`으로 죽는다. 결측은
  `pd.isna`를 거치는 `_int`/`_float` 헬퍼로 받는다(1.26.271).
- **분자만 NaN을 건너뛰는 가중평균.** `(v * w).sum() / w.sum()`은 pandas가 분자에서만 NaN을 빼 준다.
  분모도 같은 행에서 세야 한다(`frame.loc[v.notna()]`).
- **`/maps`는 `networkidle`로 기다리면 타임아웃이다.** 지도 iframe이 외부 타일을 계속 받는다.
  `domcontentloaded` + 짧은 대기로 본다.
- **폼은 돌고 있는 동안 사라진다(설계).** 중복 제출 시험은 UI로는 못 하고 직접 POST해 409를 봤다.
- **서버는 PowerShell로 끈다.** `pkill`은 윈도우에서 안 죽는다 — `pbr-run` 스킬 그대로다.
