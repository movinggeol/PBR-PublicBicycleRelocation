## ① 주말에 PC를 켜 둔다 — 게이트 C

**왜 사람만 할 수 있나.** 수집기 설정은 이미 맞습니다. 두 환경 모두
`--include-holidays`(매일 07:00–23:00)로 걸려 있는데도 주말이 통째로 비는
이유는 **그 시간에 PC가 꺼져 있었기 때문**입니다. 코드로 고칠 수 없습니다.

**현재 상태.** `stock_history`는 평일 13일 / **휴일 1일**(08-30, 1틱)입니다.
논문은 모든 단계에서 평일·휴일을 나누는데 **휴일 쪽 근거가 시뮬레이션뿐**입니다.

⚠️ **결정 뒤 첫 주말(09-05·06)도 그대로 비었습니다.** 2026-09-08에
*"주말·공휴일에도 PC를 켜 둔다"* 고 정했는데 아직 한 번도 실행되지
않았습니다 — 이 문서를 쓰는 이유이기도 합니다.

**얼마나 모여야 쓰나.**

| 쓸 곳 | 필요한 것 |
| --- | --- |
| 휴일 순수요 분포 | 휴일 **4일 이상** (= 주말 2회) |
| 논문 *"휴일도 관측했다"* | 최소 **2~3주말** |
| 휴일 도로 계수(게이트 B) | 휴일 **10일** = 주말 5회 → 빨라야 **10월 하순** |

📌 **주말 하루를 빠뜨릴 때마다 게이트 B가 1주일씩 밀립니다.** 주말마다
2일씩만 쌓이기 때문입니다.

### 🔴 2026-09-12 발견 — **PC를 켜 두는 것만으로는 부족했다**

주말 첫날(09-12 토) 확인해 보니 **도로는 받았는데 재고가 멈춰 있었습니다.**
마지막 관측이 **09-11 08:00**이고, 그 뒤로 로그에 실패 한 줄조차 없었습니다.

```text
LastResult = 0x800710E0   (요청 거부됨)
```

**파이썬이 시작조차 못 했습니다** — 스케줄러가 프로세스를 띄우기 전에
거부했으므로 수집기 코드는 무죄입니다. `PBR도로시간수집`은 같은 시각
같은 계정으로 성공(0x0)했는데 `PBR재고수집`만 거부됐습니다.

#### 원인은 **절전(sleep)** 이고, 배터리는 그리로 가는 지름길입니다

계정·세션·`pythonw.exe`를 하나씩 지웠습니다 — 같은 계정·같은 실행 파일로
최소 작업을 만들어 예약하니 **성공(0x0)** 했고 파일까지 썼습니다. 남은 것은
전원이었고, 전원 정책을 읽어 보니 이렇습니다.

```text
절전까지 — AC(어댑터): 180분 · DC(배터리): 30분
```

🔴 **범인은 배터리 자체가 아니라 절전입니다.** 절전에 들어간 뒤에는
스케줄러가 트리거를 `0x800710E0`으로 거부합니다. **배터리로 돌아도 깨어
있으면 정상 수집됩니다** — 실제로 배터리 상태에서 11:40 자동 틱이 `0x0`으로
성공했습니다.

⚠️ 다만 배터리에서는 **30분**이면 절전에 듭니다. 10분 간격 수집은 그 뒤
전부 거부되므로, 결과만 보면 *"배터리라서 멈췄다"* 처럼 보입니다.
**어댑터를 꽂으면 180분**이라 훨씬 안전할 뿐, 세 시간 자리를 비우면
어댑터를 꽂아 두어도 똑같이 멈춥니다.

🔴 **`DisallowStartIfOnBatteries=false`는 이 문제를 막지 못합니다.** 그 설정은
*"배터리라고 해서 시작을 막지 마라"* 일 뿐, 잠든 PC를 깨우지는 않습니다.

📌 **왜 도로만 멀쩡했나.** 도로는 하루 몇 번뿐이라 깨어 있는 순간에 걸렸고,
재고는 10분마다라 대부분 절전 구간에 떨어졌습니다. **둘 다 같은 원인인데
빈도 때문에 한쪽만 증상이 보인 것**입니다.

▶ **주말에는 어댑터를 꽂고, 절전을 '안 함'으로 두는 편이 확실합니다.**
(설정 → 시스템 → 전원 → 화면 및 절전) 화면만 꺼지는 것은 괜찮습니다 —
문제가 되는 것은 **절전**뿐입니다.

⚠️ **그래서 "PC를 켜 뒀다"가 곧 "수집됐다"가 아닙니다.** 절전에 들어가면
켜 둔 것과 무관하게 멈춥니다.

▶ **주말마다 `status`를 한 번 보십시오.** 켜 두는 것과 별개의 확인입니다.

```powershell
.\scripts\collector.ps1 status
```

마지막 줄의 **`마지막 : ... · 성공`** 과 오늘 날짜의 틱 수를 봅니다.
`요청 거부됨`이나 `로그온 세션 없음`이 보이면 **로그아웃·화면잠금·절전을
의심**하고, 급하면 손으로 한 틱 받아 둘 수 있습니다:

```powershell
.\scripts\collector.ps1 now
```

📌 이 발견 자체가 왜 이 문서가 필요한지 보여 줍니다 — 09-08에 *"주말에 PC를
켜 둔다"* 고 정했지만, **켜는 것만으로는 안 된다는 것**은 실제로 주말에
확인해 보고서야 알았습니다.

## ② 회사 PC에서 정본 스냅샷을 내보낸다 — 게이트 A의 선행 조건

**왜 사람만 할 수 있나.** 파일이 **다른 PC(회사환경 A)에 있습니다.**
이 PC(집환경 B)의 `station_info`에는 `2026-05-21 18` · `2026-08-26 23` ·
`2026-08-27 23` 셋뿐이고, 논문 6.3·6.5 표가 쓰는 정본
**`2026-08-11 real`이 없습니다**(2026-09-10 실측, 2026-09-11 재확인).

🔴 **다시 만들 수 없습니다.** `station_info.stock`은 실행하는 순간의
**라이브 API 재고**라, 오늘 다시 돌리면 오늘 재고가 들어옵니다.

**언제 막히나.** 게이트 A 채택 절차(수집완료_계획 2-4)의 **④단계**입니다.
스위치를 켜기 전에 정본 라벨을 박아 두어야 대조군 표를 재현할 수 있습니다.
09-15에 절차를 시작해서 ④에서 멈추면 그때 회사에 가야 합니다.

```powershell
# ① 회사환경(A)에서
python tools/transfer_run.py --list          # 라벨이 있는지 먼저 확인
python tools/transfer_run.py --export "2026-08-11 real" --out data/transfer/run_20260811_real.db

# ② 파일(약 1.4MB)을 옮긴 뒤 이 PC에서
python tools/transfer_run.py --import data/transfer/run_20260811_real.db --dry-run
python tools/transfer_run.py --import data/transfer/run_20260811_real.db
```

12개 테이블 9,124행이고 **왕복 무손실이 확인돼 있습니다**(2026-09-01).
`road_leg`는 따라가지 않습니다 — 각자 쌓는 관측이라 섞으면 안 됩니다.

📌 **A에도 없으면** 정본을 바꿔야 합니다 — 양쪽에 있는 `2026-08-26 23`을
새 정본으로 고르고 [DECISIONS 6-B](../분석/DECISIONS.md)를 고칩니다.
다만 **공표된 6.3·6.5 표를 전부 다시 재야** 하므로 옮기는 편이 훨씬 쌉니다.

## ③ NVDA 화면낭독기 점검 — 선택

**왜 사람만 할 수 있나.** 화면낭독기는 **소리로 읽습니다.** Claude는
HTML 속성이 제대로 붙었는지까지만 확인할 수 있고(테스트 13개가 그것을
지킵니다), *실제로 어떻게 들리는지*는 사람이 들어야 압니다.

**이미 한 것.** 제목 계층(h1→h2), 체크박스 묶음의 이름
(`role="group"` + `aria-labelledby`), 진행 상황 알림
(`role="status"`)을 고쳤고 테스트로 잠갔습니다(1.26.168).

절차서는 [스크린리더_점검.md](../구현/스크린리더_점검.md)에 있습니다.
