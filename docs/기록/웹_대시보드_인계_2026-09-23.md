# 웹 대시보드 기능·시각 작업 인계 (2026-09-23)

> 세션 사용량이 떨어져 **작업지시서 묶음을 시작하자마자 멈췄다.** 다른 PC·다른 세션이 이 문서만 읽고 이어 가도록
> 쓴다. 조사 결과는 원래 한 세션의 임시 폴더(scratchpad)에만 있었다 — 그 폴더는 다른 PC에 없으므로 남은
> 후보의 제안 전문을 5절에 옮겨 두었다.
>
> 앞선 점검 아홉 판(1.26.262~273)의 방법·기준·함정은 [웹_대시보드_점검_2026-09.md](웹_대시보드_점검_2026-09.md)에
> 있다. 이 문서는 그 뒤의 **기능·시각 작업**(1.26.283~) 몫이다. 이 세션은 `webapp/`만 건드린다.

## 1. 지금 어디까지 왔나

요청은 *"다른 기능적/시각적 작업"* 이었다. 일곱 관점(배차 담당자·기사·연구자 세 사람의 눈과 화면 오가기·좁은 화면·시각·
그래프)으로 화면을 훑어 45개 후보를 모으고, 겹치는 것을 합쳐 상위 20개를 골라 **후보마다 반박자 둘**이 실데이터
서버에서 재현했다. 19개가 살아남았고, 1개(C09 길찾기 단추)는 반박자 한 명이 *"어느 지도 앱인지 사용자가 먼저
정해야 한다"* 고 막았다. 나머지 25개(C21~C45)는 검증하지 않았다(6절).

살아남은 20개를 파일이 겹치는 것끼리 네 묶음으로 나눴다. 한 묶음은 **구현 → 세 검토자(정확성·규약·브라우저) →
확인된 지적 고침 → 전체 시험·순회·정합성 → 커밋**으로 돈다.

| 묶음 | 후보 | 상태 |
| --- | --- | --- |
| 1 실행 목록과 고르기 | C02 · C10 · C13 | ✅ 1.26.283 (`4abb56b`) |
| 2 실행을 따라가는 길 + `/kpi` 읽기 | C01 · C04 · C11 · C05 · C14 · C15 (+ `/kpi` 회차 이름) | ✅ 1.26.284 (`183c4d8`) |
| 3 작업지시서 (`/orders`) | C03 · C06 · C08 · C12 · C19 · C09 | ⏸ 구현 에이전트가 화면을 훑는 중에 멈췄다 — **코드 변경 없음** |
| 4 좁은 화면·인쇄·수집 현황 | C16 · C17 · C18 · C20 · C07 | 미착수 |

두 커밋 사이의 1.26.285·286은 **같은 작업 트리를 쓰는 다른 세션**(실험 쪽)의 것이다.

## 2. 사용자가 정한 것 — 다시 묻지 마라

- **길찾기 단추는 TMAP이다**(2026-09-23, *"지도 앱 길찾기 단추는 TMAP을 사용한다"*). 5절 C09의 검증자 안은
  카카오맵을 전제로 썼으니 URL만 바꿔 쓴다.
  - 링크 하나에 안드로이드·iOS 인자를 함께 싣는다:
    `tmap://route?goalname=<이름>&goalx=<경도>&goaly=<위도>&rGoName=<이름>&rGoX=<경도>&rGoY=<위도>`
    (안드로이드는 `goalname`·`goalx`·`goaly`, iOS는 `rGoName`·`rGoX`·`rGoY`를 읽는다고 알려져 있다 — **x가
    경도, y가 위도**다. 타슈 API의 `x_pos`=위도와 반대이니 뒤집지 마라).
  - `tmap://`은 **앱에서만 열린다.** 데스크톱이나 앱이 없는 폰에서는 눌러도 아무 일이 없다(1.26.48이 *"제일 나쁜
    결과"* 로 꼽은 모양). 누른 뒤 약 1.5초가 지나도 `document.visibilityState`가 `visible`이면 *"TMAP 앱이 열리지
    않았습니다 — 좌표·이름 복사 단추를 쓰세요"* 를 `aria-live`로 알린다. **복사 단추는 그대로 둔다.**
  - URL은 서버(`webapp/orders.py`) 한 곳에서 만든다. 이름은 `urllib.parse.quote(name, safe="")`로 인코딩한다
    (`KT&G`, 쉼표 든 이름이 실 DB에 있다). 좌표가 없으면 단추를 빼고, 인쇄에서는 숨기며, 차고지 복귀 행에도 단다.
  - 🔴 **TMAP API 키(`.env`의 `API_KEY`)를 HTML에 넣지 마라.** 앱 스킴은 키가 필요 없다.
  - **실기기에서 확인하지 못했다.** 버전관리 절에 인자 이름의 출처와 *"실기기 확인 필요"* 를 적고, 사용자에게
    폰(안드로이드·아이폰)으로 눌러 봐 달라고 알린다.
- **시험 실행 `2026-09-21 16 웹점검*` 다섯은 지우지 않는다** — 정리 여부는 사용자가 정한다.

## 3. 이어 가는 방법

**순서**: 묶음 3 → 묶음 4. 묶음 3 안에서는 C06(지금 보는 계획 한 줄) → C03(예산 초과·회차 요약) → C08(재고 대조
제안) → C19(표 다듬기) → C12(폰 한 대 보기) → C09(TMAP) 순으로 권한다. 앞 셋이 `_orders_context`의 같은 자리를
만지고, C12·C19·C09는 `orders.html`의 같은 표를 만진다. 한 판(1.26.28x)으로 묶어 커밋해도 되고 둘로 나눠도 된다.

**다시 쓸 도우미** — 새로 만들지 마라(두 벌이 되면 1.26.283 검토가 잡은 '최신 기준 두 벌'을 되풀이한다):

| 필요한 것 | 쓸 것 |
| --- | --- |
| 실행의 '최신' 순서 | `store.kpi_run_order` (runs.created_at — 처음 기록한 시각) |
| 실행·회차별 시간 예산 | `store.time_budgets()` / `app._row_budgets` (1.26.273). 기록이 없으면 `TIME_BUDGET_MINUTES`로 떨어지되 그렇다고 말한다 |
| 회차 이름 | 템플릿 전역 `duration_labels`, 파이썬은 `kpi_view.duration_name` |
| 실행 → 회차 두 단 고르기 | `webapp/templates/_run_picker.html`, `app._run_groups` |
| 실행 종류(계획·실험·점검) | `_run_kind(run_label)` — `plan_targets`의 `t.kind`는 1.26.283 전에 조인이 틀렸다 |
| 작업 이름 | `jobs.job_label` |
| 한 실행의 지도·데이터 | `catalog.for_run` / `catalog.run_of` |

## 4. 함정 — 이번 세션에서 실제로 걸린 것

- 🔴 **같은 작업 트리를 다른 세션이 동시에 쓴다.** 그쪽의 커밋 안 된 파일(주로 `experiments/`, `docs/분석/EXPERIMENTS.md`,
  `docs/연구/`, `tests/test_experiment_guards.py`)을 스테이징하지 마라. 파일을 이름으로 집고
  `python tools/commit_guard.py --intend <파일들>`을 먼저 돌린다. 한 파일에 두 세션의 변경이 섞이면(주로
  `docs/기록/버전관리.md`, 시험 개수 문서) 자기 몫만 `git hash-object -w --stdin --path <파일>` +
  `git update-index --cacheinfo`로 올린다. `--path`를 빼면 `core.autocrlf=true`에서 CRLF가 올라간다.
  - 실제로 그쪽 커밋(`ee2f5e5`, 1.26.285)이 README를 통째로 올리며 이쪽의 README 한 줄을 먼저 싣고 갔다.
- **판 번호가 겹친다.** 이번 세션에서 두 번 겹쳤다(279 → 283, 284는 그쪽이 285로 비켰다). 커밋 직전에
  `check_consistency`로 확인하고, 겹치면 뒤에 커밋하는 쪽이 다음 번호를 쓴다. 묶음 3은 1.26.287을 쓰려던 참이었다.
- **시험을 하나 더하면 문서 18곳 안팎의 개수가 바뀐다.** `check_consistency`가 어느 파일 몇 행인지 알려 준다.
  작업 트리의 개수에 다른 세션의 커밋 안 된 시험이 섞여 있을 수 있다 — 자기 커밋에는 자기 몫까지만 센 값을 싣는다.
- **`README.md`는 CRLF다.** 파이썬으로 고칠 때 줄끝을 보존하라.
- **셸 heredoc으로 파이썬 파일을 고치지 마라** — `\n`이 실제 줄바꿈으로 풀려 파일이 깨졌다. 편집 스크립트는 파일로 써서 돌린다.
- **증감 시험이 헛돌고 있었다**(1.26.284): `base.html`의 CSS 주석·정렬 스크립트에 ▲▼ 글자가 있어
  `"▲" in html` 같은 단정은 늘 참이다. 화면 글자를 단정할 때는 클래스나 그 절 안으로 좁혀 보라.

## 5. 남은 후보 — 제안 전문

조사(7관점 → 병합 → 후보마다 반박자 둘)에서 살아남은 것 가운데 아직 손대지 않은 11건이다.
묶음 안의 순서는 조사 번호 순이다 — 권하는 구현 순서는 3절에 있다.

후보마다 조사 시점의 문제·근거와 **반박자가 다듬은 제안**을 그대로 옮겼다. 줄 번호는 1.26.283·284 전의 것이라
어긋나 있다 — 인용된 문자열로 찾아라. 묶음 1·2가 이미 바꾼 것(예: `duration_labels` 전역, `plan_targets` 조인,
`kpi_run_order`)을 제안이 "새로 만들라"고 하면 **이미 있는 것을 쓴다.**
