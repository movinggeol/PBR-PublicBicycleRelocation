## 1. 판정 기준 — 이미 못박은 것을 다시 적는다

9장이 **결과를 보기 전에** 정한 조건입니다. 이 문서는 이것을 **바꾸지
않습니다** — 옮겨 적기만 합니다.

```text
채택: 표본 밖 MAE가 상수 속도보다 20% 이상 낮고
      + 날짜별 계수의 변동계수가 15% 미만
      + 수집 10일 이상
```

**세 조건은 AND입니다.** 2026-09-10 기준 평일은 앞의 둘을 이미 통과했고
(MAE −25.5% · 변동계수 2.2%/0.9%) 셋째만 남았습니다.

🔴 **기준 통과를 이유로 표본 조건을 앞당기지 않습니다.** 그렇게 하면
결과를 보고 기준을 고치는 것과 같아집니다. 이 원칙이 흔들리면 9장의
사전 등록 전체가 무의미해집니다.

## 2. 게이트 A — 평일 도로 10일 (예상 09-15)

### 2-1. 채택은 상수 교체가 아니라 **스위치를 켜는 것**이다

이걸 헷갈리면 계획이 통째로 어긋납니다. 지금 코드에는 **두 개의 다른 식**이
있고, 무엇을 쓸지는 `USE_ROAD_MODEL`이 정합니다.

```python
# project_config.travel_seconds()
if USE_ROAD_MODEL:            # 켜면
    return fixed + km * 3600.0 / speed        # 320.4 + km*3600/32.03
return km / speed_kmph * 3600.0               # 지금: km / 25 * 3600
```

- 지금은 **꺼져 있습니다**(`USE_ROAD_MODEL=False`). 모든 계획이 `km/25`를 씁니다.
- `ROAD_FIXED_SEC`·`ROAD_SPEED_KMPH`는 **켜야 비로소 쓰입니다.**
- 분기 지점은 `travel_seconds()` **한 곳뿐**입니다 — ILP·VRP·군집 K 추정이
  모두 이 함수를 통해서만 이동시간을 얻습니다(1.13.2 이후 규약).

📌 그래서 채택 작업의 본체는 "`.env`에 계수를 적는 것"이 아니라 **스위치를
켜고 그 아래 딸려 오는 모든 수치를 다시 재는 것**입니다.

## 4. 게이트 B — 휴일 도로 10일

### 4-1. 구조는 이미 갈라 놨다

1.26.158~160에서 끝난 일이라 **코드는 손댈 것이 없습니다**.

- `runs.day_type`으로 회귀를 갈라 평일·휴일을 절대 섞지 않습니다.
- `travel_seconds(day_type=...)`가 계수 쌍을 고릅니다.
- 휴일 계수가 비어 있으면 **평일 계수로 폴백**합니다 — "아무 값이나 쓴다"가
  아니라 지금 검증된 계수가 평일 것뿐이기 때문입니다.

### 4-2. 채택 절차

평일과 **같은 기준·같은 순서**입니다(1장·2-4). 다른 점만 적습니다.

```text
① road_time_model.py --day-type holiday 로 판정
② 통과하면 PBR_ROAD_FIXED_SEC_HOLIDAY · PBR_ROAD_SPEED_KMPH_HOLIDAY 를 채운다
③ 폴백이 더 이상 안 걸리는 것을 확인 (평일 계수와 다른 값이 나와야 한다)
④ 8장의 "평일만 재고 있다" 비대칭 문단을 지운다
```

⚠️ **휴일이 평일과 별로 다르지 않게 나올 수도 있습니다.** 그때도 값을
채웁니다 — "달랐다"가 아니라 **"재 봤더니 같았다"가 결과**입니다. 폴백에
기대는 것과 재서 같은 값을 쓰는 것은 근거의 무게가 다릅니다.

### 4-3. 언제쯤 오나

주말마다 2일씩 쌓이므로 **10일이면 5주**입니다. 공휴일이 끼면 조금

🔴 **원인은 설정이 아니라 가동 시간입니다.** 두 환경 모두
`--include-holidays`(매일 07:00–23:00)로 걸려 있는데, 주말 구간이 통째로
비어 있습니다 — 그 시간에 PC가 꺼져 있었습니다.

▶ **사용자 결정(2026-09-08): 주말·공휴일에도 PC를 켜 둔다.**
결정 뒤 첫 주말(09-05·06)도 그대로 비었습니다. **이 문서에서 유일하게
사람이 지금 당장 해야 하는 항목**입니다.

### 5-2. 얼마나 모여야 쓸 수 있나

| 쓸 곳 | 필요한 것 |
| --- | --- |
| 휴일 순수요 분포 | 휴일 **4일 이상** — 요일 효과와 그날 사정을 가를 최소치 |
| 결품 실측으로 `z`·`γ` 재조정 | 회차별 창을 덮는 날이 필요 (5-3) |
| 논문 "휴일도 관측했다" | 최소 2~3주말 |

### 5-3. 창 문제는 따로 있다 — 기다려도 안 풀린다

⚠️ **`_05_10` 회차는 원리적으로 못 덮습니다.** 가장 이른 관측이 07:00이라
05:00 시작 회차는 영영 앞이 잘립니다. **창을 앞당기는 것도 운영입니다.**

`_20_05`도 같은 이유로 9시간 중 2시간만 관측됩니다.

📌 이 둘은 게이트 C가 채워져도 남습니다 — 논문에는 **한계로 적는 편이**
맞습니다. 창을 바꾸면 그 전 자료와 잣대가 갈립니다(1.26.153이 겪은
`expected_ticks()` 함정).

## 6. 셋이 다 왔을 때 — 최종 순서

```text
A(평일 도로)  →  스위치 ON  →  실험 21개 재실행  →  EXPERIMENTS 16개 장 재작성
                                        ↓
                              P2 2-1 예산 제약 착수
                                        ↓
B(휴일 도로)  →  휴일 계수 채움  →  폴백 해제  →  8장 비대칭 문단 삭제
                                        ↓
C(휴일 재고)  →  휴일 순수요 근거  →  z·γ 재조정  →  6장 평가 다시
                                        ↓
                                  논문 최종고
```

🔴 **A를 B·C까지 기다리게 하지 마십시오.** A는 다음 주, B·C는 한 달
이상입니다. A만 먼저 채택하고, B·C는 도착하는 대로 덧붙입니다.

⚠️ 다만 **A를 켠 뒤 B가 오면 휴일 계수만 갈아 끼우면 됩니다** — 구조가
이미 갈려 있어(4-1) 재작업이 아닙니다.

## 7. 중간에 멈춰야 하는 경우

기준을 못 채우는 것도 결과입니다. **그때 무엇을 할지도 미리 정합니다.**

| 상황 | 어떻게 |
| --- | --- |
| 10일을 채웠는데 **변동계수가 15%를 넘김** | 채택하지 않는다. 날짜별 계수가 흔들린다는 것 자체가 발견 — 계절·요일을 나눠 다시 본다 |
| 10일을 채웠는데 **MAE 개선이 20% 미만** | 채택하지 않는다. 8장에 "재 봤으나 기준 미달"로 적는다 |
| 수집이 **중간에 끊김**(TMAP 한도·PC 꺼짐) | 끊긴 날을 빼고 세되, **날짜를 앞당기지 않는다** |
| 휴일 계수가 평일과 **거의 같게 나옴** | 그대로 채운다(4-2 ⚠️) |
| 예산 제약이 **21대로도 초과를 못 없앰** | 남긴 채로 보고 — 자원 제약의 측정값 |

📌 **"안 해 본 것"과 "재 보고 기각한 것"은 다릅니다.** 후자는 논문에
쓸 수 있는 결과입니다.

## 8. 이 문서를 언제 고치나

- 게이트가 하나 채워질 때마다 **0장 표를 갱신**합니다.
- 채택이 끝나면 그 장을 ✅로 닫고 **버전관리에 근거를 남깁니다.**
- 기준(1장)은 **고치지 않습니다** — 고쳐야 할 이유가 생기면 그것부터
  따로 기록하고 사용자에게 확인합니다.
