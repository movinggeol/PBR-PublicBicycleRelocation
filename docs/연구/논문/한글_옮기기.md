# 한글(HWP)로 옮기기

> 2026-09-18 작성. 원고(`.md`)를 학과 양식의 한글 파일로 옮길 때 할 일이다. **지금은 옮기지 않는다** —
> 원고가 굳을 때까지 `.md`로만 쓴다(README 머리글, 사용자 결정 2026-09-16·09-18).
>
> 근거는 `references/논문양식/`의 두 문서이다. 가이드라인이 **정한 것**(신명조 10pt · 줄간격 200% ·
> 양쪽 정렬 · 캡션 위치 · 참고문헌 규칙)과 샘플 논문에서 **잰 것**(나머지 글자 크기 · 여백 · 배치)을 가려
> 적는다. 잰 값은 어림이다. 학과의 샘플 한글 파일을 구하면 그 파일의 스타일이 이 문서보다 우선한다.

---

## 1. 언제 옮기나

다음이 모두 끝난 뒤에 **한 번** 옮긴다.

1. 게이트 A 재실행 값으로 `<!--A:` 주석 36곳을 바꾸고 지웠다(README 7-3).
2. 5.5~5.8 · 6장 · 8장 나머지 · 9장 · 초록을 썼다.
3. 장 파일의 자료 자리(`(자리`)를 모두 그림·표로 바꾸거나 지웠다(README 4-1).
4. 아래 7장의 **옮기기 전** 점검을 통과했다.

## 2. 서식

### 2-1. 샘플을 어떻게 쟀나

샘플 PDF의 지면은 515×728pt이지만, 한글의 메모 칸이 오른쪽에 붙은 채 내보낸 것이라 논문 한 쪽이
**0.762배로 줄어** 왼쪽에 들어가 있다. 표지 글줄과 쪽 번호의 가운데가 모두 x≈196pt에 있어서 쪽 너비가
약 393pt이고, 393 ÷ 0.762 = 515pt(182mm)이므로 **용지는 B5**이다. 이 배율로 되돌리면 본문이 정확히
10pt, 줄 간격이 20pt(10pt의 200%)가 되어 가이드라인과 맞는다. 아래의 pt 값은 모두 되돌린 값이다.

### 2-2. 본문

| 항목 | 값 | 근거 |
| --- | --- | --- |

| 여백(본문 영역) | 좌우 약 25mm, 위 약 24mm, 아래 약 26mm | 샘플 |

## 3. 요소별로 바꾸는 법

| 원고(`.md`) | 한글 |
| --- | --- |
| `# 제1장 서론` | `제 1 장 서 론`. 두 글자 제목은 글자 사이를 띄운다(`서 론`, `결 론`) |
| `## 1.1 …`, `### 2.2.1 …` | 절·소절 제목 스타일 |
| 도입 문단이 없는 장(1·2·5·7·8장은 `## n.1`부터 시작) | 샘플은 장 제목 바로 아래 도입 문단을 둔다. 3·4장은 도입 문단이 있다. 2·5·7·8장은 n.1절(개요·이 장의 성격)이 그 역할을 하므로 그대로 두고, 1장은 서론이라 샘플처럼 바로 본문으로 들어가도 된다 |
| `**굵은 글씨**` (정의되는 용어의 첫 등장) | 샘플 본문에는 굵은 글씨가 없다. 굵게 둘지 지도교수께 확인하고, 아니면 보통 글씨로 |
| `*기울임*` (문서·계획 이름 등) | 「」(문서 제목)이나 작은따옴표로 |
| `$…$` 문장 속 수식 | 한글 수식(문장 안) |
| `$$ … \tag{3.1} $$` | 한글 수식(가운데) + 오른쪽 번호 `(3.1)` |
| 마크다운 표 + `<표 n-m> 제목` | 한글 표. 제목은 위 가운데, 수치 열은 오른쪽 정렬, `주:` 문단은 표 바로 아래 |
| 이미지 + `[그림 n-m] 제목` | 그림 가운데, 제목은 아래 가운데. 그림 파일은 300dpi로 다시 뽑고 너비는 본문 폭(약 132mm) 이하 |
| 번호 목록 `1.` | `1)` (샘플) |
| 글머리표 `-` | 샘플에 예가 없다. `•` 한 가지로 통일 |
| 인용 `(박정연 외, 2024)` · `박정연 외(2024)는` | 번호로 바꾼다(4장) |
| 유선 문의 `(대전교통공사 … 유선 문의, 2025년 9월 6일)` | 그대로 둔다. 번호를 매기지 않는다 |
| `<표 2-1>`의 띄어쓰기 | 가이드라인 문구는 `<표1-1>`로 붙였고 샘플 차례는 `<표 2-1>`로 띄웠다. 원고처럼 **띄운다**. 붙이라는 지적을 받으면 한꺼번에 바꾼다 |

## 4. 참고문헌 바꾸는 법

가이드라인: 15개 이상, **본문에 인용한 문헌만**, **본문에 인용한 순서대로**, '저자, 논문명, 발행처, 발행연도' 순.

### 4-1. 번호 매기기

1. 제1장부터 부록까지 본문을 순서대로 읽어 각 문헌이 **처음 인용된 순서**로 [1], [2] … 를 매긴다. 옮길 때
   일회성 스크립트로 뽑는다 — 저자-연도 패턴을 [참고문헌.md](참고문헌.md)의 항목과 맞춘다.
2. 같은 문헌을 다시 인용하면 같은 번호를 쓴다.
3. 본문의 모양은 두 가지로 바꾼다. 샘플이 둘을 함께 썼다(`…있다[1].`, `Herlocker et al.(1999)은`).
   - 괄호 인용 `…이다(박정연 외, 2024).` → `…이다[3].` (번호는 마침표 앞)
   - 저자가 주어인 문장 `박정연 외(2024)는` → `박정연 외[3]는`
   - 두 편을 함께 인용하면 `[3][7]`
4. 목록에 번호가 붙은 문헌이 본문에 한 번도 나오지 않으면 뺀다.

### 4-2. 항목 모양

학술지는 `저자, “논문명”, 학술지명, 권(호), pp. 쪽–쪽, 연도.` 꼴로 쓴다. 국외 저자는 샘플처럼 이니셜을 앞에
두고, 마지막 저자 앞에 `and`를 쓴다.

| 종류 | 예 |
| --- | --- |
| 국내 학술지 | [n] 박정연, 박지환, 이상인, “대전광역시 공공자전거 이용량 수요 예측모형 연구”, 한국데이터정보과학회지, 35(5), pp. 667–680, 2024. |
| 국외 학술지 | [n] J. Schuijbroek, R. C. Hampshire, and W.-J. van Hoeve, “Inventory rebalancing and vehicle routing in bike sharing systems”, European Journal of Operational Research, 257(3), pp. 992–1004, 2017. |
| 학술대회 | [n] E. O'Mahony and D. B. Shmoys, “Data analysis and optimization for (Citi)Bike sharing”, Proceedings of the Twenty-Ninth AAAI Conference on Artificial Intelligence, pp. 687–694, 2015. |
| 학위논문 | [n] 소윤상, “LSTM을 이용한 공공자전거 동적 상태의 재고 수준 연구”, 서울대학교 환경대학원 석사학위논문, 2018. |
| 기술 보고서 | [n] C. Contardo, C. Morency, and L.-M. Rousseau, “Balancing a dynamic public bike-sharing system”, Technical Report CIRRELT-2012-09, CIRRELT, 2012. |
| 정부 보고서 | [n] 대전광역시, “2025년도 대전광역시 교통현황조사 및 분석보고서”, 대전광역시, 2025. |
| 기사 | [n] 한지혜, “대전교통공사, AI 활용 타슈 배치 효율성 높인다”, 디트뉴스24, 2024.7.24. |
| 웹 자료 | [n] 공공데이터포털, “대전시 공영자전거 타슈 대여이력 정보”, https://www.data.go.kr/ |

- **기울임은 쓰지 않는다** — 샘플 목록에는 기울임이 없다. 논문명은 큰따옴표로 감싼다.
- **DOI는 뺀다(권장).** 샘플에 없고, 원고 목록 18편 가운데 DOI를 확인한 것이 일부뿐이라 섞으면 항목 모양이
  들쭉날쭉해진다. 기사의 URL은 남긴다(원문을 찾을 다른 길이 없다).
- **자료 출처 네 건**(공공데이터포털, 기상청, 타슈 누리집, TMAP API)은 지금 본문이 인용 표시 없이 이름만
  적는다(<표 4-1>). 가이드라인은 인용한 것만 싣게 하므로, 옮길 때 <표 4-1>의 출처 칸에 번호를 달아 목록에
  올린다. 문헌 18편만으로 15편은 넘으므로 분량 때문에 넣는 것은 아니다.
- 다른 자료의 값을 옮겨 그린 그림(예: [그림 8-1]의 보고서 값)은 캡션 끝에 번호로 출처를 단다.

## 6. 옮기는 방법

**1순위는 학과의 샘플 한글 파일을 받는 것이다.** 가이드라인 PDF에 지도교수 메모가 달려 있어 원본이 한글
파일로 돌던 양식이다. 그 파일을 받으면 스타일(장·절 제목, 본문, 캡션, 쪽 번호)을 그대로 쓰고 내용만 바꾼다.

본문을 넘기는 방법은 옮기기 전에 **3장 한 장으로 먼저 시험**해서 정한다. 3장은 수식(13개)·표·기호가 가장
많아서 여기서 되면 다른 장도 된다.

| 방법 | 되는 것 | 시험할 것 |
| --- | --- | --- |
| 장별로 붙여 넣고 스타일 적용 | 가장 확실하다 | 수식 13개 이상을 한글 수식으로 다시 입력하는 시간 |
| pandoc으로 `.docx`를 만들어 한글에서 열기 | 제목 구조와 표가 한 번에 넘어간다 | 수식이 한글에서 **편집할 수 있는 수식**으로 열리는지, 표 칸 나눔, 캡션 위치. 2026-09-18 기준 이 PC에 pandoc이 없다 |

어느 쪽이든 그림은 원본 PNG를 다시 넣는다(붙여 넣은 그림은 해상도가 떨어질 수 있다).

한글·워드 파일에는 이름과 학번이 들어가므로 **커밋하지 않는다** — `docs/연구/논문/` 아래의 `.hwp`·`.hwpx`·
`.docx`는 `.gitignore`가 막는다(2026-09-18).

## 7. 점검

### 7-1. 옮기기 전 (`.md`에서)

1. `grep -rn "<!--A:" docs/연구/논문/` → 0개
2. `grep -n "^(자리" docs/연구/논문/*장_*.md` → 0개
3. 본문이 부르는 그림·표 번호가 모두 있고, 장 안에서 나오는 순서대로 이어진다.
4. 인용한 문헌이 모두 참고문헌에 있고, 목록의 문헌이 모두 본문에 나온다.
5. `python tools/check_consistency.py` → 0건

### 7-2. 옮긴 뒤 (한글에서)

1. **분량** — 서론 첫 쪽부터 결론 끝 쪽까지 30쪽 이상.
2. 차례·그림 차례·표 차례를 한글의 차례 기능으로 다시 만들고 쪽 번호를 확인한다.
3. 장마다 새 쪽에서 시작하는지, 표 제목은 위·그림 제목은 아래인지.
4. 참고문헌 번호가 본문 첫 인용 순서와 맞는지, 15개 이상인지.
5. 쪽 번호 — 앞붙이는 로마 숫자, 본문은 1부터.
6. 표지·제출서·인준서의 날짜가 모두 같은지.

### 7-3. 제출

1. 카피킬러 결과 30% 이하.
2. 지도교수 최종 확인을 받고 그 증빙(이메일·메신저)을 남긴다.
3. 제본해 학과 사무실에 1부 낸다. 인턴십 등으로 직접 내기 어려우면 기한 안에 도착하도록 우편·등기로 보낸다
   (지도교수 확인 증빙 포함).

가이드라인은 1~3장의 요령(본문 서식·분량·표절·부록·성능평가 환경, 참고문헌, 그림·표)을 채운 논문만
지도교수가 검토한다고 적는다.
