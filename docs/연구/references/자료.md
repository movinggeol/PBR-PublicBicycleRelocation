> 읽고 내린 판단은 [README.md](README.md), 논문 한 편씩의 분석은
> [LITERATURE.md](../LITERATURE.md), 논문에 실을 목록은 [참고문헌.md](../초안/참고문헌.md)에 있습니다.
>
> 🔴 **PDF는 커밋하지 않고, 글(기사 URL 목록·메모 txt)과 이 목록은 커밋합니다** (2026-09-15,
> 사용자 결정). 2026-08-27에는 폴더째 막아 **기사 URL 목록까지 한쪽 PC에만** 남았습니다.
> PDF를 계속 막는 이유는 **원격 저장소가 공개(public)** 라서입니다 — 푸시하면 논문 PDF(저작권)와
> 학번이 적힌 레포트가 누구에게나 보이고, 약 190MB가 지워도 이력에 남습니다.
>
> 📌 그래서 **PDF 링크는 파일을 넣어 둔 PC에서만 열립니다.** 다른 PC에서는 이 표로 무엇이
> 있어야 하는지 보고, 파일은 git 밖(USB·클라우드 드라이브)으로 옮깁니다.

## 새 자료를 넣을 때

1. 파일은 `참고 자료/`에 둡니다(논문은 `참고 자료/논문/`).
2. **이 문서의 표에 한 줄** 넣습니다. 기사는 URL까지 이 표에 적습니다 — `기사 url.txt`는
   처음 받아 적은 원문으로 두고, **색인은 이 문서**입니다.
3. 읽음은 ◻로 시작합니다. 읽으면 판단은 README에, 논문이면 LITERATURE 카드에 옮기고
   여기 표시를 고칩니다.
4. 논문 본문에 인용하면 [참고문헌.md](../초안/참고문헌.md)에 올립니다.
5. PDF는 `.gitignore`가 막으므로 **이 표가 다른 PC로 가는 유일한 기록**입니다. 다른 PC에도
   필요하면 파일은 git 밖으로 옮깁니다.

**읽음 표기** — 📖 읽음(수치·방법을 옮김) · 📄 일부만 · ◻ 아직 안 읽음 · 🖼 이미지뿐이라
텍스트가 안 나옴(OCR 필요). 논문의 세부 확인 수준(서지·초록·본문)은 LITERATURE 머리의
표를 따릅니다.

파일명에 공백·괄호가 있어 링크를 `<...>`로 감쌌습니다 — GitHub에서 눌리고,
`tools/check_consistency.py`의 링크 검사는 이 꼴을 건너뜁니다.
