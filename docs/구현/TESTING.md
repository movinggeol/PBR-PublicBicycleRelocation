> 실제 DB를 건드리지 않고 재현했습니다 — 바깥 환경의 `PBR_DB_PATH`를 표지 DB로 두고

## 4. 자동화하지 않은 검증

### 외부 API (TASHU · TMAP)

둘 다 **무료 요금제**입니다 — 불러도 요금이 청구되지 않고 **일일 호출 한도만**
있습니다(1.26.210 정정: 그 전까지 이 자리에 *"유료 API"* 라고 적혀 있었습니다).
그래도 자동 테스트에는 넣지 않습니다 — **CI에서 매번 돌면 한도가 금방 마르고**,
그러면 그날 사람이 쓸 몫이 없습니다. 대신 변경 시 수동으로 확인합니다.

> 아껴야 할 것은 돈이 아니라 **그날 남은 호출 수**입니다. 그래서 *"부르지 마라"*
> 가 아니라 *"자동 반복으로 태우지 마라"* 가 규칙입니다 — 결과를 눈으로
> 확인해야 하는 작업이라면 세션이 직접 불러도 됩니다.

#### 🔴 그날 도로 수집이 안 끝났으면 20건을 남기고 부른다 (1.26.215)

도로 수집기(`tools/collect_road_time.py`)가 **같은 키·같은 일일 한도**로 매일
**20건**(사슬 5 × 회차 4)을 씁니다. 2026-09-14에 지도 재그리기와 파이프라인이
150건 넘게 쓰자, 이튿날 07:14 수집이 두 엔드포인트 모두 `429 QUOTA_EXCEEDED`로
**0구간**이 됐습니다 — 게이트 A 10일째 날이었습니다.

그래서 TMAP을 부르는 시험·작업(`redraw_maps.py --with-route`, `--skip-map` 없는
파이프라인, 수동 엔드포인트 확인)은 **먼저 아래를 거칩니다.**

1. **오늘 수집이 끝났는지 본다** — `python tools/collect_road_time.py --status`에서
   오늘 라벨(`roadprobe-YYYY-MM-DD`, 휴일은 `roadprobe-holiday-YYYY-MM-DD`)이
   회차 4개 × 100구간으로 차 있으면 그대로 불러도 됩니다.
2. **안 차 있으면 수집기를 먼저 돌린다** — `python tools/collect_road_time.py --if-needed`.
   채운 회차는 건너뛰므로 여러 번 돌려도 한도를 더 쓰지 않습니다.
3. **그럴 수 없으면 20건을 남긴다** — 남은 한도는 밖에서 보이지 않으므로
   `PBR_TMAP_MAX_CALLS`로 이번 작업의 호출 수를 묶습니다. `routeSequential30`(다중 경유지 안내 30)의 한도가
   하루 100건이니(`routeSequential100`은 50건, `routeSequential200`은 20건, 무료 요금제)([step3 문서](steps/step3_visualization.md)), 그날 **같은 키를 쓰는
   모든 PC·세션의 합계**가 80건을 넘지 않게 합니다.

📌 **`tools/redraw_maps.py --with-route`는 이 셋을 스스로 합니다 (1.26.219).** 오늘 수집이
**이 PC의 DB에서** 얼마나 찼는지 말하고, **실행 전체의 예산**(`--tmap-budget` > 바깥
`PBR_TMAP_MAX_CALLS` > 기본 80건)을 넘기지 않으며, 예산이 모자란 회차의 경로 지도는 반쯤
그리지 않고 건너뜁니다. 예전에는 그 도구가 회차마다 프로세스를 따로 띄워 3단계의
`PBR_TMAP_MAX_CALLS`가 **프로세스마다 새로** 걸렸습니다 — 규칙을 적어 둔 날(1.26.215)에도
도구로는 지킬 수 없었습니다. ⚠️ 다른 PC·세션이 그날 쓴 호출은 여전히 모릅니다 — 합계는
사람이 봅니다. `--skip-map` 없는 **파이프라인**도 같은 판단을 씁니다 (1.26.222) — 시작할 때
오늘 수집 상태와 이번 예산(바깥 `PBR_TMAP_MAX_CALLS` > 35건)을 찍고(`--dry-run`에서도), step3가
끝까지 못 부를 회차는 그리지 않고 건너뜁니다.

⚠️ **한도가 몇 시에 풀리는지는 아직 모릅니다.** 한국 시간 자정은 아닙니다 —
09-15 07:26에도 두 엔드포인트가 막혀 있었습니다. 같은 날 **12:32에는 `routeSequential30`이
풀려 있었습니다**(최소 요청 한 건 성공). 풀림은 그 사이이고, 후보인 09:00(UTC 자정)과

한도 합을 넘은 것으로 설명됩니다(호출 수는 429 시도까지 센 값이라 정확한 배분은 모릅니다. 그때는 200을 쓰지 않았고, 1.26.226부터 20건이 더해져 합 170건입니다). 그러니 **전날 저녁에 태운 호출도
이튿날 아침 수집을 먹을 수 있습니다.** 풀리는 시각을 확인하기 전까지는 수집

### 파라미터 실험

`z`·`γ` 같은 모델 파라미터는 "맞다/틀리다"가 아니라 **맞바꿈(trade-off)** 이라
단위 테스트로 판정할 수 없습니다. 대신 실데이터 실험으로 근거를 남깁니다
→ [EXPERIMENTS.md](../분석/EXPERIMENTS.md), 재현 스크립트는 [experiments/](../../experiments).

파라미터를 바꿀 때 지켜야 할 것:

- **한 회차만 보고 판단하지 않는다.** 3회차 전부로 재확인한다 (틀린 적 있음).
- **`γ`는 비단조다.** γ=2000이 γ=1000보다 나빴다 — 두 점 사이를 보간하면 안 된다.
- **`z` 실험을 개선률·목표 도달률로 판정하지 않는다.** 두 지표가 `target_qty`를
  분모로 삼아 z에 딸려 움직인다. 결품 시간으로 비교한다.

| **파생** | **6장** | 결론·초록이 **원본에 없는 수치**를 만든 것 (1.26.139) |
| **링크** | 문서가 적은 상대경로 | 문서끼리 건 링크가 실제 파일을 못 찾는 것 (1.26.148) — 코드 담장(``` / ~~~) 안의 인용은 면제 |
| **규약** | 코드(예: `db.py`)의 현재 동작 | 이미 고친 규약을 문서가 아직 현재형으로 가르치는 것 (1.26.151) — 정정문·인용문(`>`)과 `docs/기록/`·`EXPERIMENTS.md`는 면제 |
| **그림** | `초안/그림/`의 파일 · 원고 본문 · 앞붙이 차례 | 셋이 다른 목록을 말하는 것 (1.26.257) — **만들어 두고 원고에 싣지 않은 그림**, 없는 파일을 가리키는 링크, 캡션 없는 참조, 본문이 한 번도 안 가리키는 표·그림, 차례 누락, 다 그렸는데 남은 *(자리)* 표시 |
| **인용** | `논문/참고문헌.md` · 원고 본문 | 인용과 참고문헌이 **서로를 가리키지 않는 것** (1.26.260) — 참고문헌에 없는 인용, 아무도 인용하지 않는 항목, **본문이 이름을 적지 않는 자료 출처**. 서술형 `저자 외(2013)`와 괄호형 `(저자, 2022)`를 모두 봅니다 |
| **부록** | `pipeline/`의 원본 코드 | 부록 B(핵심 코드)의 발췌가 **지금 코드와 다른 줄인 것** (1.26.261) — 원본에 없는 줄, 파일 이름 없는 발췌, 없는 파일을 가리키는 발췌. 앞뒤 공백과 순서는 보지 않고, 부록에서 새로 단 `#` 주석은 건너뜁니다 |

**값이 *맞는지*는 보지 않습니다.** 코드가 말하는 값과 문서가 말하는 값이
*같은지*만 봅니다 — 코드가 틀렸으면 이 검사는 조용히 통과합니다.

### 파생 검사 — 결론·초록은 새 수치를 만들면 안 됩니다 (1.26.139)

9장 결론과 초록은 **앞 장을 압축한 글**입니다. 거기 처음 나오는 숫자는
근거가 없는 숫자입니다. 그래서 두 문서의 모든 수치가 6장에 **문자 그대로**
있는지 봅니다(장 번호·연도처럼 압축한 글이 당연히 새로 쓰는 수는 뺍니다).

```
X [파생 문서] docs/연구/초안/9장_결론.md:67 — '375'이(가) 원본(6장…)에
  없습니다. 반올림했거나 새로 만든 수치입니다
      회차당 375~459km로 그리디(322~373km)보다 세 회차 모두에서 길다(6.3).
```

📌 **이건 가정이 아니라 실제로 있었던 일입니다.** 9장 초안이 6.3의
`374.7~458.5km`를 `375~459km`로 반올림해 **6장에 없는 범위**를 만들었습니다.
반올림은 사소해 보이지만, 심사자가 그 숫자를 찾으러 6장에 가면 없습니다.

### 그림 검사 — 만들어 두고 싣지 않은 자료를 잡습니다 (1.26.257)

원고 6장은 대조군 비교를 담는 **핵심 장인데 그림이 0개**였습니다. 그림 6-1·6-2·6-3은
파일도 있고 초안에도 실려 있었지만 원고 본문과 그림 차례 어디에도 없었습니다.

원고 README 4-1의 '자리' 규칙은 이것을 못 잡습니다 — 자리 표시는 **아직 만들지 않은**
자료만 세기 때문입니다. *만들어 두고 싣지 않은* 자료는 사람이 장을 넘겨 봐야만 보입니다.

```
X [그림] docs/연구/초안/그림/그림6-2_결품분포.png — 그림 파일이 있는데
  **원고가 싣지 않았습니다**. 실을 자리가 없으면 FIGURE_EXEMPT에 까닭과 함께 적으십시오
```

⚠️ **줄머리에 있다고 캡션이 아닙니다.** 원고는 `<표 2-1>은 …`처럼 표 번호로 문장을
시작합니다. 이 검사를 처음 돌렸을 때 그런 다섯 줄을 캡션으로 잘못 읽었습니다. 그래서
**자리로 가릅니다** — 표 캡션은 바로 아래가 표이고(캡션이 두 줄로 접히는 것도 봅니다),
그림 캡션은 바로 위가 이미지 링크입니다.

### 인용 검사 — 참고문헌이 본문에 닿지 않는 것을 잡습니다 (1.26.260)

참고문헌은 도로 이동시간의 출처로 *티맵모빌리티 TMAP API*를 실었는데, 원고는 <표 4-1>에서도
*"상용 경로 안내 API"* 라고만 적고 있었습니다. **같은 표의 다른 행은 출처를 이름으로 적습니다** —
그 한 줄만 아무 데도 닿지 않는 참고문헌이었고, 부록의 *"API 키가 필요하다"* 도 어느 서비스인지
말하지 않아 재현하려는 사람이 찾을 수 없었습니다.

```
X [인용] 자료 출처 '티맵모빌리티'를 참고문헌이 싣는데 **원고 본문이 한 번도 이름을
  적지 않습니다** — 쓰지 않으면 참고문헌에서 빼십시오
```

⚠️ **줄 단위로 읽으면 안 됩니다.** 원고는 `Ghosh` 다음 줄에서 `외(2017)`로 이어집니다.
이 검사를 처음 돌렸을 때 그렇게 갈린 멀쩡한 인용 **스무 건**을 짝이 없다고 물었습니다.
문서를 한 줄로 이어 붙인 뒤에 봅니다.

### 부록 검사 — 복사본은 원본이 바뀌어도 조용합니다 (1.26.261)

학과 양식은 구현한 프로그램의 **핵심 코드**를 부록으로 요구합니다. 그런데 부록 B의 발췌는
복사본이라, 원본이 바뀌어도 아무 일도 일어나지 않습니다. 심사자가 부록과 저장소를 대조하면
바로 드러나는 자리인데도 사람이 눈으로 맞춰 보는 수밖에 없었습니다.

발췌의 코드 줄을 원본에서 한 줄씩 찾습니다. 앞뒤 공백과 순서는 보지 않습니다 — 부록은
들여쓰기를 덜어 내고 갈래 하나를 걷어 내기 때문입니다.

```
X [부록] docs/연구/논문/부록_핵심코드.md:212 — 이 줄이 pipeline/step2_optimize/vrp.py에
  **없습니다**. `python tools/make_appendix_code.py`로 다시 뽑으십시오
      score = distance / (possible + 1e-9)
```

발췌는 손으로 옮기지 않습니다. `tools/make_appendix_code.py`가 **줄 번호로** 뽑으므로,
코드를 고친 뒤 그 스크립트만 다시 돌리면 부록이 따라옵니다. 줄 번호가 어긋나면 이 검사가
먼저 물으므로 범위를 고치고 다시 돌립니다.

### 논문 검사만 규칙이 다릅니다 (1.26.138)

다른 검사는 진실의 출처(코드·pytest 수집·`git log`·문서 자신)를 돌 때마다 직접
읽지만, 논문 수치의 출처는 실험 CSV입니다. `data/`와
`*.csv`는 커밋되지 않으므로 **CI가 읽을 수 없습니다.** 그래서 값을 검사기에
적어 두되, 돌 때마다 **정본 절에 그 값이 실제로 있는지 먼저 확인**합니다.

```
X [무재배치 결품 (25년 11월 `_05_10`)] 정본(...6장...)에 '2.40'이(가) 없습니다
  — 정본이 바뀌었다면 `tools/check_consistency.py`의 값을 함께 고치십시오
```

📌 **이 안전장치가 없으면 검사기 자신이 낡은 값을 지키는 또 하나의 판이
됩니다.** 6장을 다시 재면 검사기가 먼저 걸려서, 값을 옮겨 적으라고 알립니다.

⚠️ **범위는 논문 본문뿐입니다**(`README.md` + `docs/연구/초안/`).
`docs/분석`·`docs/기록`은 **날짜가 박힌 기록**이라 옛 값을 그대로 두는 것이
맞습니다 — EXPERIMENTS 5장이 아직 2.00을 적고 있는 것은 낡은 것이 아니라
**2026-08-26에 그렇게 쟀다**는 뜻입니다.

**왜 만들었나** — 1.26.134에서 핵심 결과가 **네 판으로 갈려 있던** 것을 사람이
눈으로 찾았습니다. 6장은 12개월 $n=36$인데 1장·2장·COMPARISON·LITERATURE는
5개월 $n=15$였고, README는 2026-08-26 판이라 결품 절댓값 자체가 달랐습니다.
직전 판(1.26.133)이 6장만 고치고 나머지를 갱신 범위에 안 넣은 탓입니다.

### 오탐을 늘어놓지 않도록 좁게 잡았습니다

처음 돌렸을 때 51건이 나왔는데 그중 대부분이 오탐이었습니다 — *"전체 43개
클러스터"* 를 테스트 개수로, *"국내 문헌 10편"* 을 전체 편수로 셌습니다.

📌 **오탐만 늘어놓는 검사기는 무시당해, 지켜지지 않는 규칙과 똑같아집니다.**
그래서 세 가지 장치를 뒀습니다.

- `min_value` — 테스트 개수는 세 자리입니다. 두 자리 이하는 *"테스트 5개 추가"*
  처럼 그때 늘린 몫이라 전체와 비교할 대상이 아닙니다.
- `allow` — 부분집합을 세는 줄을 부분 문자열로 빼 둡니다(*"`runs`부터
  `kpi_summary`까지 12개 테이블"*). 줄 번호로 잡으면 줄이 밀릴 때 깨집니다.
- `HISTORY_DOCS` — 버전관리·메모·ORIGINS·RETROSPECTIVE는 **지난 상태를 그대로
  남기는 것이 목적**입니다. 거기의 *"문헌 11편"* 은 낡은 값이 아니라 기록입니다.

반대 방향의 장치도 있습니다 — 어떤 사실이 **어느 문서에서도 안 잡히면**
그것도 실패로 봅니다. 표현이 바뀌었는데 정규식이 그대로면 검사가 조용히
죽는데, 통과만 하고 아무것도 못 잡는 검사기는 없는 것과 같기 때문입니다.

### 검사기가 만들어지자마자 잡은 것

첫 실행에서 **자기를 만든 감사(1.26.88)의 오류**부터 걸렸습니다.

| | 실측 | 문서가 말하던 것 |
| --- | --- | --- |
| 테스트 개수 | 555 | 548 — 8곳 |
| 테스트 파일 | 25 | 24 — `test_version_log.py` 행이 통째로 없었음 |

1.26.88이 *"460 → 548로 다 고쳤다"* 고 적은 뒤에도 **460이 네 곳에** 남아
있었고, THESIS.md는 같은 문서 안에서 문헌을 24편과 11편으로 함께 말하고
있었습니다. 손으로 세고 손으로 고치는 한 이 종류는 계속 남습니다.
