# 화면 디자인 시스템

대시보드 UI의 규칙을 한곳에 모았습니다. 구현은 전부
[webapp/templates/base.html](../../webapp/templates/base.html)의 `<style>` 블록 안에 있습니다.
별도 CSS 파일이나 빌드 단계는 없습니다.

## 무엇을 따랐나

Apple의 웹 디자인 언어를 기준으로 삼았습니다. 핵심은 세 가지입니다.

1. **강조색은 하나뿐입니다.** 누를 수 있는 모든 것이 같은 파란색입니다. 두 번째
   브랜드 색은 없습니다.
2. **그림자를 쓰지 않습니다.** 카드·버튼·글자에 그림자가 없습니다. 구획은 **면의 색을
   갈아 끼워서** 나눕니다(검정 → 오프화이트 → 흰색). 시스템 전체에 그림자는 딱 하나,
   지도에만 씁니다.
3. **자간이 좁습니다.** 큰 글자일수록 자간을 조입니다. Apple 특유의 조밀한 제목 느낌은
   여기서 나옵니다.

### 그대로 따르지 않은 것

원문은 **여백이 큰 마케팅 페이지** 문법입니다. 섹션마다 80px 여백, 본문 17px, 한 화면에
한 덩어리. 이 대시보드는 13열짜리 표가 있는 **실무 도구**라 그대로 옮기면 도구로 못 씁니다.

그래서 **밀도를 두 구간으로 나눴습니다.**

| 구간 | 밀도 | 근거 |
| --- | --- | --- |
| 히어로·설명 | Apple 그대로 (40px 제목, 21px 리드, 넓은 여백) | 진입 지점에서는 무엇을 하는 화면인지가 먼저 읽혀야 합니다 |
| 통계 타일 | 중간 (26px 값, 좁은 여백) | 지표 다섯 개가 **한 줄에** 들어가야 서로 견줘집니다 |
| 표·폼 | 14px, 조밀 | 한 화면에 들어오는 행 수가 곧 도구의 쓸모입니다 |

원문의 `store-utility-card`(조밀한 유틸리티 카드)와 `product-tile`(전면 타일)이 애초에
서로 다른 밀도로 설계돼 있습니다. 그 구분을 그대로 가져온 것입니다.

## 글꼴

SF Pro에는 **한글 글자가 없습니다.** 이 사이트는 거의 전부 한글이므로
**Pretendard Variable**로 대체했습니다 — SF Pro의 자소 형태와 자간을 한글까지 맞춘
오픈소스 글꼴입니다.

- 위치: `webapp/static/fonts/PretendardVariable.subset.woff2` (라이선스 `OFL.txt`)
- **저장소에 같이 담습니다.** 인터넷이 끊겨도 화면이 같아야 하는 로컬 도구입니다.
- 가변 글꼴 한 파일로 300~700을 모두 냅니다.

### 부분집합 (2.0MB → 518KB)

전체 글꼴은 2.0MB입니다. 한글 음절 11,172자가 용량의 대부분이라 라틴만 덜어내면
1.82MB밖에 안 줄어듭니다. 그래서 **KS X 1001 완성형 2,350자**로 잘랐습니다.

자를 근거를 먼저 쟀습니다 — 대여소 이름과 UI 문구를 통틀어 실제로 쓰이는 음절은
**877자**였고, 그중 **KS X 1001을 벗어나는 글자는 0개**였습니다. 2,350자면 1,473자의
여유가 남습니다.

다시 만들려면:

```bash
pip install fonttools brotli          # 빌드 전용. requirements.txt에는 없습니다
python -m fontTools.subset PretendardVariable.woff2 \
  --output-file=PretendardVariable.subset.woff2 \
  --flavor=woff2 --layout-features='*' --name-IDs='*' \
  --text-file=<KS X 1001 2350자> \
  --unicodes='U+0020-007E,U+00A0-00FF,U+2000-206F,U+20A0-20BF,U+2100-218F,U+2190-22FF,U+2460-24FF,U+25A0-26FF,U+2700-27BF,U+3000-303F,U+3130-318F,U+FF00-FFEF,U+FE0F'
```

집합 밖의 희귀 음절은 시스템 한글 글꼴로 떨어집니다. 글자가 안 보이지는 않고, 그
글자만 서체가 달라 보입니다.

## 색

역할로만 씁니다. 라이트/다크 값이 갈리는 곳은 `:root` 블록뿐입니다.

| 토큰 | 라이트 | 다크 | 쓰임 |
| --- | --- | --- | --- |
| `--blue` | `#0066cc` | `#2997ff` | **모든** 상호작용. 링크, 버튼, 현재 위치 |
| `--nav-black` | `#000000` | `#000000` | 1단 내비 |
| `--nav-flow` | `#f5f5f7` | `#141415` | 2단 내비 |
| `--canvas` | `#ffffff` | `#1d1d1f` | 카드·표 바탕 |
| `--parchment` | `#f5f5f7` | `#000000` | 페이지 바탕, 표 머리글 |
| `--ink` | `#1d1d1f` | `#f5f5f7` | 본문. 순검정이 아닙니다 |
| `--hairline` | `#d2d2d7` | `#424245` | 카드 테두리 |

**다크 값은 밝은 값을 뒤집은 게 아닙니다.** 원문에 다크 모드 규정이 없어서, 원문이
정의한 **어두운 타일 색**(`#000` / `#1d1d1f` / `#272729`)과 **어두운 면 전용 파랑**
(`#2997ff`)을 그대로 끌어왔습니다.

### 상태색은 예약돼 있습니다

`--good` / `--warning` / `--critical`은 상태 전용입니다. "네 번째 계열색"으로 쓰지
않습니다. 그리고 **색만으로 뜻을 전하지 않습니다.**

| 상태 | 색 말고 무엇이 더 붙는가 |
| --- | --- |
| 실행 상태 배지 | 점 + 글자("완료", "실패") |
| 예산 초과 행 | 붉은 배경 + `⚠` + 왼쪽 굵은 선 |
| 증감 | `▲` / `▼` 기호 |
| 진행 단계 | `✓` `●` `✕` 표시 + 오른쪽에 "완료/진행 중/실패" |
| 문장 속 링크(`.muted`·`.hint`·`.empty`) | 평소에도 밑줄(다른 `a`는 `:hover`에서만) — hover 전에는 색맹이면 옆 글자와 안 갈렸다(axe `link-in-text-block`, 1.26.126) |

> 클래스 이름은 **방향이 아니라 뜻**을 담습니다. 증감은 `.delta.good` / `.delta.bad`이지
> `.up` / `.down`이 아닙니다 — 결품 시간은 내려가는 것이 좋은 값이라 `▼`가 초록입니다.

### 범주색은 상태색·상호작용색을 빌리지 않습니다 (1.26.109)

싣기·내리기(작업 두 종류)는 **범주**입니다 — 좋고 나쁨도, 누를 수 있음도
아닙니다. 그런데 예전 웹은 싣기를 `--good-ink`(상태 전용), 내리기를
`--blue`(상호작용 전용)로 칠했습니다. 규약 위반이었을 뿐 아니라, **지도에서는
파랑이 싣기**여서 같은 파랑이 두 화면에서 정반대 작업을 뜻했습니다.

| 토큰 | 라이트 | 다크 | 지도(`mapviz.py`)의 짝 |
| --- | --- | --- | --- |
| `--pick-ink` | `#0072B2` | `#56B4E9` | `PICK_COLOR = "#0072B2"` |
| `--drop-ink` | `#b34700` | `#ff9e6b` | `DROP_COLOR = "#D55E00"` |

색 값 자체는 다릅니다 — 지도는 **채운 원**이라 순색을, 웹은 **글자**라 명암비를
맞춘 값을 씁니다(채움과 글자가 기준이 다른 것은 `--on-blue`와 같은 이유).
같아야 하는 것은 **어느 쪽이 따뜻한 색인가**뿐입니다. 두 색은 명도가 아니라
**색상으로만 갈리므로**(라이트에서 서로 대비 1.06) 반드시 글자와 함께 씁니다.

## 통계 타일

지표 **다섯 개가 1200px 안에서 한 줄에** 들어가도록 크기를 맞췄습니다.

| | 값 |
| --- | --- |
| 최소 폭 | 190px (`repeat(auto-fit, minmax(190px, 1fr))`) |
| 사이 간격 | 10px |
| 값 글자 | 26px |
| 안쪽 여백 | 13px 16px 15px |

최소 폭을 키우거나 값 글자를 키우면 **4+1로 접힙니다.** 1200px에서 좌우 여백 48px을
빼면 1152px, 간격 40px을 더 빼면 타일 하나에 222px이 돌아갑니다.

타일을 짧게 유지하려고 두 가지를 옮겼습니다.

- 증감의 비교 대상("직전 실행 … 대비")은 타일마다 되풀이하지 않고 **히어로에서 한 번만**
  말합니다.
- 긴 라벨은 잘라서 단서를 아래(`.sub`)로 내립니다 — "결품 시간 (대여소·일 평균)"이
  아니라 "결품 시간" + "대여소·일 평균 · 재배치 전 1.87시간".

## 모서리

문법을 섞지 않습니다.

| 토큰 | 값 | 쓰임 |
| --- | --- | --- |
| `--r-sm` | 8px | 조밀한 유틸리티 |
| `--r-md` | 11px | 입력칸 |
| `--r-lg` | 18px | 카드, 타일, 로그 |
| `--r-pill` | 9999px | **동작을 뜻하는 모든 것** — 버튼, 칩, 배지, 내비 항목 |

알약 모서리 자체가 "이건 누르는 것"이라는 신호입니다.

## 그림자

시스템 전체에 **하나뿐입니다.**

```css
--shadow-product: rgba(0, 0, 0, .22) 3px 5px 30px 0;
```

원문은 이 그림자를 "표면 위에 놓인 제품 사진"에만 씁니다. 이 앱에서 그에 해당하는 것은
**지도**입니다 — 계산의 최종 산출물이자 유일한 그림 자료입니다. 카드·버튼·글자에는
쓰지 않습니다.

## 내비게이션 (2단 + 작업 흐름)

```
━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━
 🚲 PBR                            API   ◐          ← 1단: 검정 44px
━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━
 재배치 계획   1 실행  2 결과  3 데이터   [계획 실행] ← 2단: 52px, 반투명+블러
───────────────────────────────────────────────────
   성과 지표 · 차량 운용 · 지도 · 작업지시서          ← 3단: ② 안에 있을 때만
```

- **1단**은 유틸리티입니다. 작업과 무관한 것(API 문서, 테마)만 둡니다.
- **2단**은 작업 순서입니다. 번호를 붙여 "1 → 2 → 3"이 순서라는 걸 색이 아니라
  숫자로 말합니다. 우측의 `계획 실행`은 어느 화면에서나 같은 자리에 있습니다.
- **3단**은 그룹 안의 페이지입니다. `② 결과`에 있을 때만 나타납니다.

현재 위치는 `request.url.path`로 판단합니다 — 라우트마다 변수를 넘기지 않습니다.

## 도움말 풍선

용어에 커서를 대거나 **키보드 초점이 가면** 설명이 뜹니다. 점선 밑줄이 "설명이 있다"는
표시입니다.

구현상 두 가지를 지켰습니다.

- **풍선은 `<body>` 바로 아래에 하나만 두고 옮겨 씁니다.** 요소마다 `::after`로 만들면
  `overflow: auto`가 걸린 표 안에서 잘립니다.
- **터치에서는 뜨지 않습니다.** 그래서 풍선에는 **보조 설명만** 담습니다. 없으면 곤란한
  정보는 본문이나 `.hint`에 적습니다.
- **비어 있을 때는 `aria-hidden`으로 감춥니다.** 풍선 상자는 하나뿐이라
  `role="tooltip"`인 채 `opacity: 0`으로만 숨는데(`display: none`이 아니다),
  그러면 뜨기 전에도 **이름 없는 빈 툴팁**으로 계속 노출됩니다(axe
  `aria-tooltip-name`, 1.26.126). `show()`/`hide()`가 `aria-hidden`을 함께
  켜고 끕니다 — 떠 있을 때만 이름이 있습니다.

화면 밖으로 나갈 것 같으면 위로 접어 넣고, 스크롤이 시작되면 닫습니다.

## 표

- 머리글 고정(`position: sticky`), 넓은 표는 자체 가로 스크롤
- 숫자 열은 우측 정렬 + `tabular-nums` + **`width: 1%`**
- 남는 폭은 `.grow`를 단 글자 열이 가져갑니다

`width: 1%`가 없으면 열이 균등 분배돼 머리글과 값 사이가 휑하게 벌어지고, 눈으로
이어지지 않습니다.

## 쪽 넘기기 (1.17.4~5)

목록이 세로로 길어지면 **쪽을 나눕니다.** 파일 목록 세 곳에 걸었습니다.

| 화면 | 전 | 후(첫 화면) |
| --- | --- | --- |
| `/` 최신 산출물 | 26행 | 10행 |
| `/data` | 122행 | 48행 |
| `/maps` | 33행 | 15행 |

| | 값 |
| --- | --- |
| 조작부 | `‹ 이전` · `N / M쪽` · `다음 ›` (모두 `.chip` 알약) |
| 한 쪽 | 5덩어리 |
| 끝 쪽 | `disabled` 속성 — 색만 흐리게 하지 않습니다 |
| 현재 위치 | `aria-live="polite"`인 `.pager-status` 문구 |

### 무엇이 한 덩어리인가 — 분류 이름이 어디 있느냐로 갈립니다

```html
<div class="card flush" data-pager="5" data-pager-label="…">
  …
  <tr data-page-item="0">…</tr>   <!-- 값이 같으면 한 덩어리로 움직인다 -->
  <tr data-page-item="0">…</tr>
```

- **`/`의 최신 산출물은 분류 단위**입니다. 한 표에 분류 13개가 들어 있고 분류
  이름이 그 분류의 **첫 행에만** 붙기 때문에, 행으로 자르면 **이름 없는 행으로
  시작하는 쪽**이 생깁니다. 그래서 한 분류의 행들이 같은 `data-page-item` 값을
  공유합니다.
- **`/data`·`/maps`는 행 단위**입니다. 분류마다 카드가 따로고 이름이 표 밖(`<h2>`)에
  있어, 행으로 잘라도 이름 없는 쪽이 생기지 않습니다. 페이저도 **카드마다** 붙고
  서로 독립적으로 움직입니다.

파일은 최신순으로 정렬돼 있으므로 **첫 쪽이 늘 가장 최근분**입니다.

- **조작부는 스크립트가 만듭니다.** 서버는 늘 전부 내려보내므로, 스크립트가 없거나
  꺼져 있으면 **예전처럼 전부 보입니다** — 내용이 사라지지 않습니다.
- 서버 왕복(`?page=2`)을 쓰지 않은 이유는 실행 화면에 **입력 폼이 함께 있어서**입니다.
  쪽을 넘길 때마다 사용자가 적어 둔 값이 기본값으로 되돌아갑니다.
- 한 쪽에 다 들어가면 조작부를 만들지 않습니다.
- 표와 조작부 사이 선은 **마지막 행의 밑줄 하나**로 냅니다. 쪽마다 보이는 마지막
  행이 달라지므로 `.paged`로 `tbody tr:last-child`의 '밑줄 없음'을 되돌립니다 —
  안 그러면 마지막 쪽에서만 선이 사라집니다.

## 표 접기 — 열과 행 (1.26.72 · 1.26.96)

쪽 넘기기가 **목록**을 다룬다면, 접기는 **표 한 장이 너무 클 때** 씁니다. 방향이
둘이라 장치도 둘입니다.

| | 열 접기 | 행 접기 |
| --- | --- | --- |
| 언제 | 가로로 길다 (`/kpi` 15열) | 세로로 길다 (`/vehicles` 21행) |
| 켜는 법 | `.col-toggle-wrap` 안의 `[data-col-toggle]` + 접을 칸에 `.col-more` | `<table data-row-limit="N">` |
| 조작부 | 표 **위** 오른쪽 (`모든 열 보기` ↔ `핵심 열만 보기`) | 표 **아래** 가운데 (`전체 N행 보기` ↔ `상위 N행만 보기`) |
| 접근성 | `aria-pressed` | `aria-expanded` |
| 감추는 법 | `table.cols-collapsed .col-more { display: none }` | 스크립트가 `tr`에 `hidden` 속성 |

- **조작부 위치가 다른 것은 일부러입니다.** 열은 머리글을 보기 전에 고르는 것이라
  위에, 행은 "여기까지가 끝"을 본 다음 더 볼지 정하는 것이라 아래에 둡니다.
- **행 접기는 서버가 이미 정렬해 보낸 순서를 전제합니다.** DB는 `vehicle_id` 순으로
  주므로(`db.vehicle_workload`의 `ORDER BY`) 그대로 접으면 `V01~V08`이라는 아무 뜻
  없는 여덟 대가 펴집니다. `vehicles_page`가 `minutes` 내림차순으로 정렬해 넘겨
  **위 막대그래프와 표의 순서를 맞춥니다**.
- **정렬하면 접기를 다시 적용합니다**(`__pbrRowsRefresh`). 처음 고른 행을 그대로
  두면 정렬해 놓고도 아까 숨은 행이 계속 숨습니다 — 페이저의 `__pbrPagerRefresh`와
  같은 이유입니다.

### ⚠️ 카드 모드는 가중치로 두 번 집니다

`[data-narrow] table.m-cards td`(0,2,2)가 `table.cols-collapsed .col-more`(0,2,1)를
이기고, `table.m-cards tr`의 `display:block`이 `[hidden]`의 `display:none`을 이깁니다.
그래서 좁은 화면용 규칙을 따로 답니다 — `!important`가 아니라 **가중치를 올려서**:

```css
[data-narrow] table.m-cards.cols-collapsed td.col-more { display: none; }
[data-narrow] table.m-cards tr[hidden]                 { display: none; }
```

### 접힌 상태의 마지막 줄

`.paged`와 같은 문제입니다. `tbody tr:last-child`의 '밑줄 없음'을 되돌리지 않으면
접었을 때 표와 조작부를 가르는 선이 사라집니다 — `table.rows-collapsed`가 되살립니다.

**같은 `pbr-*` 열쇠 체계**를 씁니다: `pbr-fold-col-<표 id>` · `pbr-fold-row-<표 id>`.

```js
pbrRecall(key, fallback)   // 저장된 값이 없거나 못 읽으면 fallback
pbrRemember(key, on)
```

바꿉니다. 남이 보낸 링크를 열었을 때 내가 예전에 걸어 둔 정렬이 얹히면 **보낸
사람이 말한 순서와 다른 화면**을 보게 됩니다.

## 표 정렬 (1.19.0)

**열 제목을 누르면 그 열로 오름/내림 정렬합니다.** 한 번 더 누르면 방향이 바뀝니다.
쪽 넘기기와 마찬가지로 **서버 왕복 없이 스크립트가 DOM만 다시 배열**합니다.

| | 값 |
| --- | --- |
| 켜는 법 | `<table data-sortable>` |
| 끄는 열 | `<th data-nosort>` (링크만 든 열) |
| 표시 | 정렬 가능 `↕`(흐림) · 오름 `↑` · 내림 `↓`(강조색) |
| 접근성 | `aria-sort="none\|ascending\|descending"`, `tabindex=0`, Enter·Space |

- **열 종류는 값에서 판단합니다.** 결측(빈칸·`—`)을 뺀 모든 칸이 숫자로 읽히면
  숫자 열, 아니면 글자 열(`localeCompare(…, "ko")`)입니다. `12.5 km`·`86분`처럼
  단위가 붙어도 숫자로 읽지만, `12.5 → 8.3시간`처럼 숫자가 둘이면 글자 열로 다룹니다.
- **결측은 오름·내림과 무관하게 늘 뒤로 보냅니다.** 안 그러면 내림차순 첫 화면이
  빈칸으로 가득 찹니다.
- **화살표 자리를 처음부터 비워 둡니다** — 정렬을 켤 때 열 너비가 흔들리지 않게.
- **쪽 넘기기가 걸린 표는 정렬 뒤 쪽 구성을 다시 만듭니다**(`__pbrPagerRefresh`).
  페이저가 덩어리 목록을 **그때그때 DOM 순서에서** 만들도록 고쳤습니다 — 처음 한 번
  읽어 두면 정렬한 뒤에 엉뚱한 쪽이 나옵니다. 정렬하면 첫 쪽으로 돌아갑니다.
- **행 접기가 걸린 표도 정렬 뒤 다시 접습니다**(`__pbrRowsRefresh`, 위 '표 접기').

### 걸지 않은 표

- **`/`의 최신 산출물** — 분류 이름이 그 분류의 **첫 행에만** 붙습니다. 행을 흩으면
  이름 없는 행만 남습니다(쪽 넘기기에서 덩어리를 나눈 것과 같은 이유).
- **`/guide`의 설명 표(`.table-prose`)** — 읽는 순서가 곧 내용입니다.
- **`/runs/{id}`의 실행 정보** — 열 제목이 없는 이름:값 표입니다.

**인라인 SVG를 파이썬이 직접 만듭니다**(`webapp/charts.py`). 차트 라이브러리를

### 어떤 마크를 쓰나 (1.26.78)

`charts.py`가 내는 것은 다섯입니다. **고르는 기준은 그림의 모양이 아니라 축의
성격**입니다.

| 함수 | 쓰는 곳 | 고르는 기준 |
| --- | --- | --- |
| `line` | 실행별 추세 | x가 **순서**를 뜻하고 값의 오르내림이 관심사일 때 |
| `hbar` | 값 자체를 보여줄 때 | 항목 **이름이 길고 순서가 없고**, 묻는 것이 *"얼마인가"*일 때(가로로 눕혀야 이름이 들어간다) |
| `deviation_hbar` (1.26.109) | 차량별 누적처럼 **형평성**을 볼 때 | 묻는 것이 *"고른가"*일 때. `hbar`를 차량 21대(339~402분, 폭 16%)에 썼더니 전부 같은 길이로 보였다 — 막대는 **평균에서 떨어진 만큼**이고 세로선이 평균이다. 절대값은 커서 풍선과 아래 표에 남긴다. 기준은 으로 **부르는 쪽이 정한다**(1.26.112) |
| `vbar` | 시간대·요일별 | 항목이 **순서가 있고 이름이 짧을 때**. 24개를 `hbar`로 쌓으면 세로가 600px을 넘어 한눈에 안 들어옵니다 |
| `scatter` | 효과 대 비용 | 두 지표의 **관계**가 관심사일 때 |
| `heatmap` | 시간대 × 요일 | 두 축의 **격자마다** 값이 있을 때 |

`vbar`는 강조 막대(`highlight`)와 구분선(`dividers`)을 받습니다 — 주말이나 회차
경계처럼 **"여기가 다르다"**를 말할 때 씁니다. ⚠️ 다만 **색이 혼자 뜻을 나르지
않습니다**: 부르는 쪽이 `divider_note`로 글자 설명을 함께 냅니다("붉은 막대 =
주말"). 아래 '지키는 규칙'의 마지막 항목과 같은 이유입니다.

`line`의 x축 이름은 **기본이 처음·끝뿐**입니다. 실행 라벨(`2026-08-28 도로실측2`)이
길어 다 적으면 겹치기 때문입니다. `2025-01`처럼 짧고 규칙적인 이름이면
`all_ticks=True`로 전부 보여 줄 수 있습니다(칸이 좁으면 건너뛰며 적습니다).

### 지키는 규칙

| 규칙 | 왜 |
| --- | --- |
| **축이 둘인 그래프를 만들지 않습니다** | 단위가 다른 두 지표를 한 판에 겹치면 두 축의 정렬이 임의가 되고, 없는 상관관계가 있는 것처럼 보입니다. 지표마다 **작은 그래프를 따로** 냅니다 |
| **0 기준이 언제나 정직하지는 않습니다** (1.26.109) | 0 기준은 *"값이 얼마인가"*를 물을 때 옳습니다. *"고른가"*를 물을 때는 **고른 상태(평균)가 기준**이라야 하고, 그때 0 기준은 폭이 좁은 값들의 차이를 지워 버립니다. 축을 잘라 과장하는 것과 반대 방향의 실수입니다 — `deviation_hbar`를 씁니다 |
| **기준선은 무엇을 세는지 밝히고 잽니다** (1.26.112) | 평균을 그리기 전에 **무엇이 평균에 들어가는지** 정해야 합니다. 차량 누적에서 `0분`은 "일이 없었다"가 아니라 "아직 한 번도 안 나갔다"인데, 그 0을 섞으면 기준선이 끌려 내려와 **일한 차량이 전부 평균 위**로 그려집니다(21대 중 4대가 놀면 기준이 275.2분, 일한 17대는 모두 `+64.8분`). 어느 값이 기준에 드는지는 그리는 함수가 판단할 수 없으므로 `deviation_hbar(baseline=...)`로 **부르는 쪽이 정합니다** — 막대는 전부 그리되 기준만 옮기고, 무엇을 뺐는지 화면에 적습니다 |
| **크기로 값을 말하면 눈금과 함께 하한도 밝힙니다** (1.26.112) | 크기 인코딩은 눈금 없이 못 읽지만, 눈금은 **말할 수 없는 것도** 말해야 합니다. 불균형 지도의 반지름은 `max(3, improvement)`라 3에서 막히는데 `improvement`는 0이나 음수(계획이 악화시킨 곳)일 수 있어, 악화된 점과 3대 해소한 점이 픽셀까지 같습니다. 눈금을 그냥 "3대"라 적으면 **거짓 주장**이 됩니다 — `≤3대`로 적고, 크기로 구분되지 않는 것은 **모양(점선 테두리)** 으로 가릅니다 |
| **가로 스크롤 0건이 "읽힌다"는 뜻은 아닙니다** (1.26.115) | 좁아지면 브라우저가 **줄을 바꿔 넘침을 없앱니다** — `scrollWidth > clientWidth` 검사는 통과합니다. 그런데 두 글자 낱말이 한 글자씩 세로로 서면 넘치지 않아도 못 읽습니다(400% 확대에서 내비 단추 라벨이 그랬습니다). 라벨이 짧고 접히면 안 되는 곳에는 `white-space: nowrap`과 `flex-shrink: 0`을 함께 겁니다 — **옆의 링크에는 있는데 단추에만 빠져 있었습니다.** 검사는 `Range.getClientRects()`로 실제 그려진 줄 수를 세야 합니다 (상자 높이로 짐작하면 44px 터치 타깃을 전부 2줄로 잘못 셉니다) |
| **넘칠 때만 끊습니다** (1.26.115) | `word-break: break-all`은 **다음 줄에 통째로 들어갈 토큰까지** 갈라 `_05_10`이 두 동강 났습니다. `overflow-wrap: anywhere`는 먼저 토큰째 다음 줄로 내리고 그래도 안 맞을 때만 쪼갭니다 — 넘침은 여전히 막으면서 멀쩡한 토큰은 살립니다 |
| **계열이 하나면 범례를 두지 않습니다** | 제목이 이미 무엇인지 말합니다. 계열을 늘리는 대신 그래프를 늘립니다 |
| **한 색만 씁니다** | 강조색은 하나라는 규칙이 그래프에도 적용됩니다. 산점도에서 회차를 색으로 나누지 않고 **점 옆 글자와 커서 설명**으로 구분합니다 |
| **값 표시는 골라서** | 꺾은선은 **끝점 하나만** 적습니다. 점마다 숫자를 적으면 읽히지 않습니다 |
| **격자·축은 실선 머리카락선** | 점선은 "예측"이나 "임계"로 읽힙니다. 그냥 격자일 때는 실선입니다 |
| **테두리가 아니라 틈** | 히트맵 칸은 2px 틈으로 나눕니다. 겹치는 점은 면 색 링으로 떼어 놓습니다 |
| **커서만으로 읽게 두지 않습니다** | 모든 그래프에 `표로 보기`(`<details>`)가 붙습니다. 커서 설명은 `data-tip`이라 키보드 초점으로도 뜹니다 |
| **표는 카드가 아니라 창으로 띄웁니다** (1.21.3) | 카드 안에서 펴면 그래프가 밀려나 **둘을 나란히 볼 수 없습니다.** 떠 있는 창(`position: fixed`)으로 내고 **머리를 끌어 옮길 수 있게** 합니다 — 그래프 옆에 놓고 맞대어 보라는 것입니다. 처음 자리는 **세로 중앙 · 가로는 중앙에서 살짝 오른쪽**입니다 — 화면 끝에 붙이면 넓은 모니터에서 본문과 멀어져 시선이 크게 튑니다. 머리글은 `sticky`, 창은 화면 밖으로 못 나갑니다 |
| **표의 소수 자릿수를 고정합니다** (1.21.2) | `round(2)`는 `0.30`을 `0.3`으로 줄여 **소수점이 세로로 어긋납니다.** `"%.2f"|format`으로 자리를 맞춥니다(`tabular-nums`와 짝입니다) |
| **히트 영역은 마크보다 큽니다** | 8px 점을 정확히 짚게 만들지 않습니다(약 24px) |
| **표를 펴도 옆 카드가 늘어나지 않습니다** (1.21.1) | 그래프 카드 그리드(`.viz-grid2`)에 `align-items: start`를 줍니다. CSS Grid 항목은 기본이 `stretch`라, 한 카드에서 `표로 보기`를 펴면 **같은 행의 다른 카드가 그 높이만큼 함께 늘어나** 아래가 텅 빈 채로 커집니다 |

### 발산 척도 — 여기서만 두 번째 색조를 씁니다

순수요는 **부호가 있는 값**입니다(양수면 빠져나감, 음수면 쌓임). 한 색조의 농담으로는
방향을 말할 수 없으므로, 요일 × 시간 히트맵만 **파랑 ↔ 빨강 + 무채색 가운데**를 씁니다.

| 토큰 | 뜻 |
| --- | --- |
| `--viz-pos-1..4` | 빠져나감(채워 줘야 함). 따뜻한 쪽 |
| `--viz-neg-1..4` | 쌓임(빼내야 함). 찬 쪽 |
| `--viz-zero` | 0 근처. **무채색** |

- 두 극이 **서로 반대로 읽혀야** 합니다. 파랑↔청록처럼 둘 다 찬 색이면 방향이 안 보입니다.
- **가운데에 색을 두지 않습니다.** 색이 있으면 "아무 일도 없음"이 값처럼 읽힙니다.
- 0 근처가 면 색으로 물러나는 것은 발산·순차 척도에서 허용된 규칙입니다. 대신
  **척도 범례와 표 보기를 반드시 함께** 냅니다 — 색만으로 값을 읽게 두지 않습니다.
- 다크 값은 밝은 값을 뒤집은 것이 아니라, 어두운 면에서 0이 물러나도록 따로 고른
  단계입니다(어두운 쪽이 0, 밝은 쪽이 큰 값).
- 단계는 램프의 명도가 단조로 증가하고 인접 단계가 눈에 띄게 벌어지는지 검증한
  값입니다(색조 하나, 명도 단조, 인접 ΔL 확보).

작업지시서(`/orders`)만 인쇄를 전제합니다. **차량 한 대가 한 장**이라야 기사에게
그대로 건넬 수 있습니다.

## 모바일 모드 (1.26.47)

위의 유동형 반응형과 **별개로**, 사용자가 직접 켜고 끄는 모드입니다. 상단
내비의 **`모바일`** 단추로 전환하며, 폭과 무관하게 강제됩니다 — 데스크톱에서
현장 화면을 미리 보거나, 폭은 넓지만 손가락으로 쓰는 기기에서 바로 켭니다.

**규칙은 `[data-narrow]` 하나에만 겁니다.** 폭 판정을 CSS가 하지 않는 것이
핵심입니다 — `@media`는 버튼으로 끌 수 없어서, 폭으로도 버튼으로도 켜지게
하려면 규칙을 두 벌 적어야 하고 그러면 한쪽만 고치게 됩니다. 대신 스크립트가
폭과 버튼을 함께 보고 `<html data-narrow>`를 붙였다 뗍니다.

상태는 셋이고 `localStorage`(`pbr-view`)에 남습니다:

| 값 | 뜻 |
| --- | --- |
| (없음) | 폭이 560px 이하면 모바일 — 기본 |
| `mobile` | 폭과 무관하게 모바일 |
| `desktop` | 폭과 무관하게 데스크톱(좁은 화면에서 일부러 끈 경우) |

바뀌는 것은 넷입니다.

1. **표가 카드로 눕습니다.** `.m-cards`를 단 표만 해당하고, `<td>`마다
   `data-label`로 머리글을 데려갑니다 — 머리글 줄이 사라지므로 그것이 각 칸이
   무슨 값인지 아는 유일한 단서입니다. 빈 라벨(`data-label=""`)은 값만 넓게
   쓰는 칸입니다(순번·대여소처럼 그 자체로 무엇인지 아는 것).
2. **긴 묶음을 접습니다.** `<details class="m-fold">`로 감싸면 좁은 화면에서만
   접힙니다. `<details>`라 스크립트가 없어도 열립니다.
3. 내비·여백을 줄이고 **터치 타깃 44px**을 지킵니다.
4. 지도 iframe이 `65vh`가 됩니다.

**인쇄는 이 모드를 무시합니다.** 모바일로 켠 채 인쇄해도 작업지시서는 차량
한 대가 한 장이어야 하므로, `@media print`가 카드를 표로 되돌립니다.

### 카드 모드의 정렬 줄

머리글이 숨겨지므로 누를 곳이 없어집니다. 표 앞에 단추 줄(`.m-sortbar`)을
스크립트가 만들어 세웁니다 — **정렬 자체는 머리글의 `th.__pbrSort`를 그대로
부릅니다.** 규칙을 두 벌 만들면 같은 열을 같은 방향으로 정렬했는데 데스크톱과
모바일의 결과가 달라집니다. 방향은 색만이 아니라 화살표(▲▼)로도 말합니다.

### 터치 타깃

**누르는 것은 전부 44px 이상입니다.** 표 안의 링크는 글자가 작아 16~21px밖에
안 됐는데(`/data` 100개, `/maps` 30개), 글자를 키우면 표가 길어지므로
`inline-block` + 세로 여백 + 음수 마진으로 **누를 면만** 키웠습니다.

⚠️ **이 문장이 한동안 사실이 아니었습니다** (1.26.94에서 정정). 위 작업은
**표 안의 링크**만 고친 것인데 규약은 "전부"라고 적어 두어, 정작 손대지 않은
**실행 폼**이 검사에서 빠졌습니다 — 실측이 체크박스 22px(라벨 포함)·입력칸
38px·셀렉트 40px이었고, `/run`은 모바일 작업 흐름의 1단계입니다.

| 대상 | 어떻게 채우나 |
| --- | --- |
| 표 안의 링크 | `inline-block` + 세로 여백 + 음수 마진 (표 길이를 늘리지 않는다) |
| 폼 입력칸·셀렉트 | `min-height: 44px` + 세로 패딩 |
| 체크박스 | **네모는 16px로 두고 감싼 `<label>`이 44px을 갖는다** — 네모를 키우면 글자와 견줘 커 보이고 기기마다 다르게 그려집니다 |

**예외 하나: 문장 속 인라인 링크는 키우지 않습니다.** WCAG가 *문장 안의
인라인 타깃*을 크기 요건에서 명시적으로 제외합니다(2.5.5·2.5.8). 억지로
키우면 문단 줄간격만 망가집니다 — 지표를 좇아 화면을 나쁘게 만들지 않습니다.

### 표 머리글의 `scope`

`<thead>` 안이면 `scope="col"`, 본문 행의 첫 칸이면 `scope="row"`를 답니다.
없으면 스크린리더가 셀과 머리글을 잇지 못합니다 — 1.26.94 이전에는 **93개
전부** 빠져 있었습니다. `tests/test_webapp.py`가 위치까지 함께 봅니다
(값이 뒤바뀌면 없느니만 못하므로).

### 인쇄

인쇄는 이 모드를 무시합니다. 모바일로 켠 채 인쇄해도 작업지시서는 차량 한
대가 한 장이어야 하므로, `@media print`가 카드를 표로 되돌립니다.

> ⚠️ 되돌릴 때 **빈 라벨 칸(`td[data-label=""]`)도 함께** 적어야 합니다.
> 그 화면 규칙은 가중치가 (0,3,3)이라 인쇄의 `td`(0,2,3)보다 구체적이어서,
> 빠뜨리면 **첫 칸만** `block`으로 남아 표 밖으로 떨어집니다(실측).
> `.no-print`를 감추는 규칙도 공용 인쇄 블록에 있어야 합니다 — 예전에는
> `orders.html`에만 있어서 다른 화면의 정렬 줄이 종이에 나왔습니다.

## 자르는 규칙은 값의 종류를 따릅니다 (1.26.99)

같은 자리에 들어가는 작은 회색 글씨라도 **파일명과 문장은 다르게 다룹니다.**

| 클래스 | 담는 것 | 넘칠 때 |
| --- | --- | --- |
| `.step-file` | 파일명 (`pipeline/step1_cluster/top_st_clustering.py`) | `nowrap` + 말줄임표로 **자릅니다** |

파일명은 뒤가 잘려도 어느 단계인지 알아보지만, 설명은 잘리면 뜻이 사라집니다.

> ⚠️ **겪은 일** — `/guide`가 `.step-file`을 설명 문장에 재사용해 **모바일에서

> 170px 칸에). 하필 **처음 쓰는 사람을 위한 화면**인데 정작 설명이 안 보였습니다.
> 템플릿이 `style="font-family:inherit"`을 인라인으로 덮어쓰고 있었던 것이
> 단서였습니다 — 클래스가 안 맞는다는 걸 알면서 한 속성만 고친 것입니다.
> **클래스가 반쯤 맞으면 인라인으로 덧칠하지 말고 새로 만드세요.**

### 고칠 수 있는 칸의 안내는 서버가 미리 적을 수 없습니다

원천 CSV 경로가 칸보다 88px 길어, 좁은 화면에서는 앞의 `data/raw_data/…`만 보이고
어느 달 자료인지 말해 주는 파일 이름이 밀려 있었습니다. 이름을 아래에 따로 적되,
**서버가 렌더링할 때 적어 두면 사용자가 값을 고치는 순간 어긋납니다** — 스크립트가
지금 값에서 뽑고 `input` 이벤트로 따라갑니다.

**넘칠 때만 보여줍니다**(`scrollWidth > clientWidth`). 경로가 다 보이는 데스크톱에서는
같은 말을 두 번 하는 셈이라 오히려 방해가 됩니다.

## 명암비 — WCAG 2.1 AA (1.26.102)

**본문 크기 글자는 4.5:1, 큰 글자(24px 이상 또는 18.66px 이상 굵게)는 3:1**입니다.
여덟 화면을 라이트·다크 양쪽에서 실측해 맞췄습니다. 걸린 것은 셋이었습니다.

| 무엇 | 전 | 후 |
| --- | --- | --- |
| `--ink-4` (라이트) | `#86868b` — 흰 3.62 / 오프화이트 3.33 | `#707074` — 4.93 / 4.53 |
| `--on-blue` (다크) | `#ffffff` on `#2997ff` — 3.02 | `#1d1d1f` — 5.58 |
| 예산 초과 행의 흐린 글자 | `--ink-3` on `--critical-soft` — 4.42 | `--ink-2` — 11.02 |

- **두 바탕 모두에서 잽니다.** 오프화이트(`--parchment`)가 흰색보다 빡빡해서,
  흰 바탕만 보면 통과로 착각합니다. `--ink-4`가 정확히 그랬습니다.
- **`--ink-4`는 장식이 아닙니다.** `.hint`·`.sub`·`.empty`·`.step-note`·눈금까지

### ⚠️ 파랑 하나가 두 역할을 다 하지는 못합니다

`#2997ff`는 Apple이 **어두운 면의 글자색**으로 정의한 파랑입니다(어두운 바탕에서
5.58:1). 이 앱은 같은 색을 단추·현재 위치의 **채움색**으로도 쓰는데, 그러면
관계가 뒤집혀 위에 올린 흰 글자가 3.02:1이 됩니다.

**파랑을 어둡게 해서는 못 풉니다.** 흰 글자가 통과할 만큼 어둡게 하면(`#0066cc`)
이번엔 링크 글자가 어두운 바탕에서 3.02로 깨집니다. 그래서 **채움색은 두고 그
위의 글자를 어둡게** 했습니다 — `--on-blue`가 애초에 그 역할의 토큰입니다.

### 경고 색 위에서는 글자를 진하게

붉은 바탕 위 흐린 회색이 4.42:1이었습니다. 바탕을 밝히면 맞출 수 있지만 그러면
경고가 흐려집니다 — **예산을 넘긴 행은 읽어야 하는 행**이라 반대로 갔습니다.

## 인쇄 — 접은 것은 종이에서 전부 편다 (1.26.102)

화면의 접기·쪽 넘기기는 **좁은 화면을 위한 편의**지 내용을 줄이는 것이 아닙니다
(서버는 늘 전부 내려보냅니다). 그런데 **종이에는 스크롤도 단추도 없습니다.**

> ⚠️ **겪은 일** — 이 규칙이 없어 인쇄물이 말없이 빠뜨리고 있었습니다:
> `/vehicles` 차량 21대 중 **8대**, `/kpi` 15열 중 **5열**, `/data` 156행 중
> **50행**. 화면에는 펴는 단추가 있으니 아무도 눈치채지 못했습니다.

```css
table.rows-collapsed tbody tr[hidden] { display: table-row !important; }
table.cols-collapsed .col-more        { display: table-cell !important; }
[data-page-item][hidden]              { display: table-row !important; }
```

### 화면 골격은 선택자로 지웁니다

내비 세 줄(44+53+52px)이 첫 장 위를 먹고, 종이에서 누를 수 없는 필터 칩·쪽
단추·열 접기 단추가 그대로 찍혔습니다. **`.no-print`를 템플릿마다 붙이게 두면
빠뜨립니다** — 실제로 `orders.html`에만 9개 붙어 있었고 나머지 화면은 0개였습니다.
그래서 구조 선택자로 한 번에 겁니다.

## 표 팝업 — 좁은 화면에서는 자리를 잡지 않습니다 (1.26.102)

좁은 화면의 표 팝업은 **아래에서 올라오는 판**이라 자리를 CSS가 잡습니다
(`left: 0; right: 0`). 그런데 `pin()`이 `right: auto`로 바꾸면 그 묶음이 풀려
**폭이 내용에 맞춰 늘어납니다.**

> ⚠️ 실측 — 390px 화면에서 판이 **1072px**이 되고 창도 판도 가로로 밀리지 않아,
> 수요 구조 표 **25열 중 16열을 볼 방법이 아예 없었습니다.** 색만으로는 값을 못
> 읽으니 이 표가 히트맵의 대안인데, 정작 그 대안이 잘려 있었던 것입니다.
> `drag()`는 이미 같은 이유로 좁은 화면을 건너뛰고 있었고 **`open()`만 빠져**
> 있었습니다 — 판정을 `NARROW_PANEL` 하나로 모았습니다.

## 바꿀 때

1. 색은 **반드시 토큰으로** 씁니다. 템플릿에 hex를 직접 쓰지 않습니다.
2. 다크 값을 추가하면 **세 곳 모두**에 넣습니다 — `:root`,
   `@media (prefers-color-scheme: dark)` 안의 `:root:not([data-theme="light"])`,
   `:root[data-theme="dark"]`. 이렇게 해야 토글이 OS 설정을 양방향으로 이깁니다.
3. 두 번째 강조색을 만들지 않습니다.
4. 그림자를 늘리지 않습니다. 강조가 필요하면 **면을 갈아 끼웁니다.**
5. 상태를 색으로만 말하지 않습니다. 표시나 글자를 함께 붙입니다.
