# 시각화 방식 조사 — html을 계속 쓸 것인가

> 수정안 24번(*"시각화에 html 말고 더 나은 방안이 존재하는가? 바로 수정하지 말고
> 조사 정도만"*)에 대한 답입니다. **조사 문서이고, 이 문서를 쓰면서 코드는 한 줄도
> 바꾸지 않았습니다.** 무엇을 고칠지는 25·26번과 함께 정하면 됩니다.
>
> 2026-08-26 작성. 측정은 모두 저장소의 실제 산출물에서 냈습니다.

---

## 0. 요약

**결론부터: 형식(html)이 문제가 아닙니다. 지금 html이 자립하지 못하는 것이 문제입니다.**

지도 1장을 열려면 **CDN 5곳에서 자원 11개**를 받아야 합니다. Leaflet 본체까지
외부에서 받으므로 **인터넷이 끊기면 지도는 빈 화면입니다.** 형식을 PNG나 다른
라이브러리로 바꾸는 것보다, 지금 html을 자립시키는 쪽이 **작업량이 훨씬 적고 얻는
것이 큽니다.**

그리고 이것은 **이 저장소가 이미 내린 결정과 어긋납니다** — 웹 대시보드의 그래프는
정확히 반대로 만들어져 있습니다(`webapp/charts.py`: 외부 JS 없음, 인라인 SVG,
*"인터넷이 끊겨도 화면이 같아야 한다"*). 지도만 예외입니다.

## 1. 지금 무엇을 쓰고 있나

| 무엇 | 어디 | 만드는 법 | 자립? |
| --- | --- | --- | --- |
| 군집·경로·재고 **지도** | `step3_map/`, step1, step4 | folium 0.20 → Leaflet html | ❌ CDN 11개 |
| 대시보드 **그래프** | `webapp/charts.py` | 파이썬이 인라인 SVG를 직접 씀 | ✅ 완전 자립 |

같은 프로젝트 안에서 두 방식이 정반대입니다. 그래프 쪽에는 왜 그렇게 했는지가
파일 첫머리에 적혀 있는데, 지도 쪽에는 그런 기록이 없습니다.

### 실측 (저장소의 산출물 69장)

```
지도 html 69장, 합계 11.0 MB, 평균 163 KB
  clusterd_map  27장
  imbalance_map 33장
  vrp_map        9장   ← 평균 730 KB, 나머지의 7배
```

`vrp_map`이 무거운 이유는 **TMAP이 준 도로 좌표**입니다. 한 장을 뜯어 보면:

```
전체        706.1 KB
좌표 리터럴 390.9 KB  (55%)   ← 폴리라인 109개
마커        106개
```

즉 **부풀린 것은 라이브러리가 아니라 데이터**입니다. 라이브러리를 바꿔도 이 55%는
그대로 남습니다. 이 점이 아래 비교의 전제입니다.

## 2. 진짜 문제 — 자립하지 못한다

`vrp_map` 한 장이 참조하는 외부 자원 (실측):

```
cdn.jsdelivr.net      leaflet.js / leaflet.css / bootstrap / leaflet-textpath
                      fontawesome / leaflet.awesome.rotate.css
cdnjs.cloudflare.com  leaflet.awesome-markers.js / .css
code.jquery.com       jquery-3.7.1.min.js
netdna.bootstrapcdn   bootstrap-glyphicons.css
tile.openstreetmap.org  배경 타일
```

**로컬에 인라인된 Leaflet 코드: 없음.**

그래서 이런 일이 생깁니다.

- 현장·차고지에서 **인터넷이 약하면 지도가 안 뜹니다.** 기사에게 주는 산출물인데
  네트워크에 기대고 있습니다. **이것이 유일하게 큰 문제입니다.**
- 참조 11개 중 **하나는 버전이 박혀 있지 않습니다** — folium 저장소를 직접
  가리키므로(`cdn.jsdelivr.net/gh/python-visualization/folium/...`) 그쪽이 파일을
  바꾸면 **과거 지도의 표시도 같이 바뀝니다.** 다만 마커 회전용 CSS라 영향은 작습니다.
- 파일을 열 때마다 외부로 요청이 나갑니다(호스트 5곳, 실측 645ms).

> ### ⚠️ 정정 (1.22.5) — "재현 불가"는 과장이었습니다
>
> 처음 이 문서는 *"CDN이 버전을 내리면 과거 산출물이 통째로 재현되지 않는다"* 고
> 적었습니다. **확인해 보니 틀렸습니다.** 나머지 10개는 URL에 버전이 박혀 있고,
> 실제로 받아 보니 **2015년 leaflet 0.7.7도, 2016년 jQuery 1.12.4도 아직 살아
> 있습니다.** 버전이 고정된 CDN 자원은 사라질 이유가 거의 없습니다.
>
> 재현성을 근거로 자립화를 정당화할 수 없습니다. **남는 논거는 오프라인 하나**이고,
> 위의 버전 없는 참조 1건입니다.

⚠️ **이건 형식의 문제가 아니라 포장의 문제입니다.** PNG로 바꾸면 자립하지만
(3-A), 그건 자립을 얻으려고 상호작용을 버리는 것이라 값이 비쌉니다.

## 3. 선택지

### 3-A. PNG/정적 이미지 (matplotlib·contextily)

- 얻음: 완전 자립, 파일이 작다, 논문에 그대로 넣는다.
- 잃음: **확대·팝업·레이어 끄기가 전부 사라진다.** 25번(호버 팝업)과 정면으로
  충돌한다. `webapp/charts.py`가 PNG를 거부한 이유도 같다 — 다크 모드에서 흰 판이
  뜨고 값을 읽을 수 없다.
- 판정: **지도에는 부적합.** 다만 **논문 그림용으로 따로** 뽑는 것은 유용하다.

### 3-B. 다른 JS 라이브러리 (plotly / bokeh / kepler.gl)

- 얻음: 더 나은 상호작용.
- 잃음: **문제가 그대로다** — 셋 다 결국 JS 번들이 필요하고, 기본 저장은 역시
  CDN을 참조한다. plotly는 `include_plotlyjs=True`로 자립할 수 있지만 그때
  **한 장에 +4.35 MB**다(실측: plotly.js 번들. folium 인라인 666 KB의 6배 이상).
  새 의존성도 는다
  (현재 셋 다 설치되어 있지 않다).
- 판정: **바꿀 이유가 약하다.** 지금 아쉬운 것은 라이브러리의 표현력이 아니다.

### 3-C. 지금 folium을 자립시킨다 — **보류 (사용자 결정, 2026-08-26)**

folium에는 자원을 넣어 주는 선택지가 없다(`folium.Map`의 인자를 확인했다).
**저장한 html을 후처리**하면 된다. 실제로 시제품을 만들어 **외부 스크립트·
스타일시트 0개**로 뜨는 것을 확인했다(5 KB → 161 KB).

⏸ **다만 지금은 하지 않기로 했다.** *"인터넷 끊겨도 볼 수 있다는 것 제외하고
이점이 있냐"* 는 물음에 재 보니 **없었다.** 첫 로딩 645 ms는 캐시되면 0이고,
재현성 논거는 위에서 정정했다. 파일은 오히려 **+166 KB/장 커진다**(11 MB → 22 MB).
현장에서 인터넷 없이 써야 할 일이 생기면 그때 한다.

#### 재개할 때 알아야 할 것 (측정해 둔 값)

**① 666 KB 중 실제로 필요한 것은 266 KB뿐이다.**

| 자원 | 크기 | 쓰나 |
| --- | --- | --- |
| leaflet.js + css | 157 KB | ✅ 지도 본체 |
| awesome-markers | 6 KB | ✅ 출발·도착 마커 |
| textpath.js | 3 KB | ✅ 이동 방향 화살표 |
| fontawesome (CSS 99 + 글꼴 276) | **375 KB** | ⚠️ **play/stop 아이콘 2개용** |
| jQuery · bootstrap · glyphicons | 367 KB | ❌ **한 번도 안 쓴다** |

산출물에서 `jQuery` 호출 0회, `fa-` 아이콘은 `fa-rotate` 하나다. folium이
**쓰든 안 쓰든 템플릿에 무조건 박아 넣기** 때문이다(`folium.Icon`을 빼고
저장해도 참조 10개가 그대로 나오는 것을 확인했다).

**② `folium.Icon` → `DivIcon`으로 바꾸면 fontawesome 375 KB가 통째로 빠진다.**
step3는 방문 번호 마커에 **이미 `DivIcon`을 쓰고 있다** — 같은 방식이면 된다.

**③ 공유 폴더 방식(예전 권장안)은 쓸 수 없다.** 지도는 `/files/{relpath}`로
**독립 파일로 열리고 사용자가 내려받기도 한다**. 공유 자원을 참조하게 만들면
**파일을 옮기거나 받는 순간 깨진다.** 자립시킨다면 **파일마다 인라인**이 맞다.

**④ 후처리는 URL 목록을 코드에 박지 말고 html에서 훑어야 한다.** folium을
올리면 목록이 바뀌어 조용히 깨진다. 그리고 치환할 때 **`re.sub`의 치환
문자열로 JS 본문을 넘기면 안 된다** — 본문 속 `\s` 같은 것이 이스케이프로
해석돼 터진다(실제로 겪었다). 람다로 넘길 것.

**⑤ 배경 타일은 별개다.** 타일까지 자립시키려면 대전 영역을 미리 받아야 하는데
양이 크고 OSM 이용약관 확인이 필요하다. 타일이 없어도 마커·경로·팝업은 그려지므로
"빈 화면"은 면한다.

### 3-C'. 안 쓰는 것만 떼어낸다 — **자립화를 안 할 거라면 이쪽**

인터넷과 무관하게 이득이다. 한 번도 쓰지 않는 **742 KB**(jQuery·bootstrap·
fontawesome)를 매번 받고 있다. 떼면 **파일은 커지지 않고**(링크가 줄어 오히려
조금 작아진다) 로딩만 빨라진다. 남는 것이 leaflet 157 KB뿐이라, 나중에 자립화로
마음이 바뀌면 그것만 넣으면 된다.

⏸ 이것도 지금은 보류다 — 사용자가 다른 일을 먼저 하기로 했다.

### 3-D. 좌표를 줄인다 (형식과 무관, 같이 할 만함)

`vrp_map`의 55%가 도로 좌표다. 폴리라인 단순화(Douglas–Peucker)로 눈에 띄는
변화 없이 줄일 수 있다. **다만 경로 길이·소요시간 계산에는 절대 쓰면 안 된다** —
표시용으로만 줄이고, 거리는 원본으로 잰다. 섞으면 KPI가 조용히 틀어진다.

## 4. 권장 순서

1. ~~자립화~~ → **보류.** 이점을 재 보니 오프라인 하나뿐이었다(3-C).
   **현장에서 인터넷 없이 써야 할 일이 생기면** 그때가 할 때다.
2. ~~25번(호버 팝업)·26번(UI/UX)~~ → **완료 (1.22.3).** html을 유지하기로
   했으므로 folium 팝업·CSS 작업이 됐다. 3-A/3-B를 골랐다면 둘 다 다시 짜야 했다.
3. **안 쓰는 742 KB를 떼는 것(3-C')** 이 자립화보다 먼저다 — 파일이 커지지 않는다.
4. **3-D(좌표 단순화)는 여유가 있을 때.** 표시용에 한정한다.
5. **논문 그림은 따로 PNG로** 뽑는다(3-A). 화면용과 지면용은 요구가 다르다.

**바꾸지 말아야 할 것**: `webapp/charts.py`의 인라인 SVG 방식. 이미 자립하고
있고 다크 모드까지 맞물려 있다. 지도를 그 원칙 쪽으로 끌어오는 것이 방향이다.

## 6. 이 문서가 남긴 교훈

**"더 나은 방안이 있는가"를 물으면 대안을 찾게 되지만, 먼저 잴 것은 지금 것의
무엇이 아픈가다.** 처음 이 문서는 대안(PNG·plotly·자립화)을 늘어놓고 자립화를
권했다. 그런데 사용자가 *"오프라인 말고 이점이 있냐"* 고 되묻자 **근거 하나가
과장이었음이 드러났고**(재현 불가), 남은 이점은 캐시되면 사라지는 645 ms뿐이었다.

- **인용하기 전에 확인할 것.** "CDN이 버전을 내리면 재현 불가"는 그럴듯했지만,
  실제로 받아 보니 2015년 버전도 살아 있었다. 재 보지 않고 쓴 문장이었다.
- **비용도 같이 적을 것.** 자립화의 +166 KB/장을 처음부터 크게 적었다면 권장이
  달라졌을 것이다.
- **덜어내기가 채우기보다 먼저다.** 666 KB를 어떻게 넣을까만 보다가, 그중
  **742 KB가 애초에 안 쓰이는 것**이라는 사실은 나중에야 쟀다.
