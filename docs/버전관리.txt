1.0 -> 1.0.1
1.0 : 작년의 바이브코딩 버전 -> 1차적으로 직접 수정한 상태.
1.0.1 : 대전교통공사 타슈 관제센터와의 통화 후 최대 적재량을 15대->10대로 수정.
	'step1'의 '1.top_clustering.py'을 주로 수정함.
		- 기존에는 클러스터 사이즈 기준('target_cluster_size': int =7)보다 크면
			대여소를 '보낼' 군집후보('from_cand'), 작으면 대여소를 '받을' 군집후보'to_cand'로 설정하였음.
			하지만 이럴 시, '군집 크기'를 주로 고려하기 때문에 정작 중요한 '군집별 작업 균형'(balance)를 
			고려하지 못하게 됐음.
			-> Pick 또는 Drop 대여소가 특정 군집에 과도하게 집중되는 balance 불균형 문제가 발생함.
		- 우선적으로 from_cand와 to_cand 선정 조건을 사이즈 기준 초과/미만으로 하지 않고, 기준 +2보다 
		크거나 작다는 등 유연하게 적용함. balance와 size는 적절하게 되어었다. 모든 대여소의 abs(balance) < 5 
		였으며 size 또한 기준 +-2였다. (다만 시간이 오래 걸린다. 5분 이상. 이걸 개선할 예정)
1.0.2 : 'step1'의 '1.top_clustering.py'을 주로 수정함.
		-  cluster size를 기준으로 sender/receiver 군집을 선정하고, balance 부호에 따라 Pick 또는 Drop 대여소만 이동하도록 
			제한하였다. 또한 cluster size 범위를 유지하고, 극단적인 imbalance 발생 시 
			emergency mode를 통해 balance 우선 조정을 수행하여 군집 간 불균형을 완화하였다.
