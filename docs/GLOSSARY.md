>
> 현장에서 쓰는 짧은 설명은 웹의 [사용 안내](WEBAPP.md) `/guide` 화면에도 있습니다.
> 그쪽은 기사·운영자용 여덟 낱말이고, 이 문서는 **코드와 문서를 읽을 때** 쓰는 전체

## 1. 계획의 단위 — 무엇을 언제 계획하는가

| 말 | 코드 | 뜻 |
| --- | --- | --- |
| **회차** | — | 차량이 차고지를 떠나 대여소를 돌고 **차고지로 돌아올 때까지** 한 번. 하루에 여러 번 돕니다. |
| **시간대** | `duration` | 회차가 겨냥한 **5시간 창**. `_05_10`(05~09시)·`_10_15`·`_15_20`·`_20_05`(20~04시) 넷뿐입니다. 창마다 자전거가 흐르는 방향이 반대라 **절대 섞지 않습니다.** |
| **창** | window | 위 시간대를 가리키는 말. 문서에서 '창'과 '시간대'는 같은 뜻으로 씁니다. |
| **기간** | `period` | 과거 수요를 뽑아 올 **달**. `25년 11월` 표기입니다. 계획 대상 달이 아니라 **학습에 쓸 달**입니다. |
| **실행 이름 / 실행 라벨** | `now`, `run_label` | 한 번의 파이프라인 실행에 붙이는 이름. 산출물 파일명과 DB 기록을 이것으로 묶습니다. **실행 시각이 아닙니다** — `datetime.now()`를 넣으면 단계 간 파일명이 어긋납니다. |
| **요일 구분** | `day_type` | `weekday`(평일) / `holiday`(휴일). **휴일 = 주말 ∪ 공휴일**이고 공휴일은 `holidays` 패키지를 따릅니다. `auto`는 계획 대상일을 달력으로 판정합니다. |
| **계획 대상일** | `target_date` | 이 계획을 실제로 집행할 날. 요일 구분과 계절 피처를 여기서 정합니다(기본값은 오늘). |

## 2. 수요 — 몇 대가 필요한가

| 말 | 코드 | 뜻 |
| --- | --- | --- |
| **순수요** | `net_demand`, `demand` | 한 시간대에 그 대여소에서 **빌려 나간 수 − 반납된 수**. 양수면 빠져나가는 곳(채워야 함), 음수면 쌓이는 곳(빼내야 함). |
| **평균·표준편차** | `mu`, `sigma` | 학습 기간의 대여소별 순수요 평균과 산포. |
| **여유 계수** | `TARGET_Z` = 1.99 | `target_qty = mu + z·sigma`의 `z`. **평균만 채우면 절반의 날은 모자라기 때문**에 더합니다. 값의 근거는 [EXPERIMENTS.md](EXPERIMENTS.md), 왜 그 값이 필요한지는 [DEMAND_DISTRIBUTION.md](DEMAND_DISTRIBUTION.md)(꼬리가 아니라 **추정 오차** 때문입니다). |
| **목표 재고** | `target_qty` | 그 시간대를 버티려면 그 대여소에 있어야 하는 대수. |
| **재배치량** | `rebal_qty` | `target_qty − 현재 재고`. **양수 = Drop 필요, 음수 = Pick 가능.** |
| **작업 문턱** | `REBAL_MIN_QTY` = 2 | `|rebal_qty|`가 이 값 **이하면 손대지 않습니다.** 한두 대를 맞추러 차를 보내는 것이 손해이고, 그 정도는 이용자가 스스로 메웁니다. |
| **목표 재고 상한** | `TARGET_QTY_UPPER_RATIO` = 1.5 | 목표 재고는 거치대 수를 그대로 상한으로 쓰지 않고 **거치대 × 1.5**까지 허용합니다. 자전거는 거치대 밖에도 세울 수 있고, 거치대가 5대뿐인 곳에서 상한을 딱 맞추면 수요를 담지 못합니다. ⚠️ 현장 확인이 안 된 값입니다. |
| **계절 보정 / 계절 배율** | `warmup`, `season_ratio` | 계획 대상 달 **첫 14일** 실적으로 도시 전체 배율 하나를 구해 `mu`·`sigma`에 곱합니다. 2월→3월처럼 수요가 도약하는 달에는 지난달 통계가 구조적으로 낮기 때문입니다. **대여소별로 나누지 않습니다.** |
| **날씨 배율** | (미도입) | 같은 자리에 날씨로 구한 하루 배율을 곱하자는 안. 측정은 끝났고 붙이는 것은 보류입니다 — [WEATHER.md](WEATHER.md) 5장. |

## 3. 대여소와 차량

| 말 | 코드 | 뜻 |
| --- | --- | --- |
| **대여소** | `station_id`, `station_name` | 타슈 대여소. 약 1,350곳. |
| **거치대** | `parking_lot` | 그 대여소에 세울 수 있는 자전거 수(하드웨어 용량). |
| **재고** | `stock` | 지금 그 대여소에 있는 자전거 수. |
| **차고지** | depot, `DEPOT_ID` = ST0001 | 타슈 관제센터. 모든 회차가 여기서 출발해 여기로 돌아옵니다. 이용자용 대여소가 아닙니다. |
| **적재 용량** | `VEHICLE_CAPACITY` = 10 | 차량 한 대가 동시에 실을 수 있는 자전거 수(대전교통공사 확인값). |
| **보유 차량 대수** | `FLEET_SIZE` (기본 21) | 굴릴 수 있는 트럭 총 대수. 실행마다 바꿀 수 있습니다. |
| **회차당 투입 상한** | `VEHICLES_PER_ROUND` | 한 회차에 동시에 낼 수 있는 최대 대수. **상한일 뿐이고 실제 대수는 그 회차의 일감이 정합니다.** |
| **군집 / 클러스터** | `cluster` | 가까운 대여소를 묶은 덩어리. **차량 1대 = 군집 1개**이므로 군집 수 = 그 회차에 나가는 차량 수입니다. |
| **차량 속도** | `VEHICLE_SPEED_KMPH` = 25 | 이동 시간 추정에 쓰는 주행 속도. **ILP와 VRP가 반드시 같은 값을 써야 합니다.** |
| **작업 시간** | `PICK_TIME_SEC`·`DROP_TIME_SEC` = 30 | 자전거 한 대를 싣거나 내리는 데 걸리는 시간. ⚠️ 현장 확인이 안 된 값입니다. |
| **시간 예산** | `TIME_BUDGET_MINUTES` = 120 | 한 회차가 끝나야 하는 기한. 넘기면 겨냥한 시간대가 지나가 계획의 효과가 줄어듭니다. **넘어도 계획을 바꾸지는 않고 표시만 합니다.** |

## 4. 최적화 — 어떻게 푸는가

| 말 | 코드 | 뜻 |
| --- | --- | --- |
| **Pick / Drop** | `pick_drop` | Pick = 자전거를 **빼 오는** 대여소(재고 과잉), Drop = **내려놓는** 대여소(재고 부족). |
| **군집화** | K-Medoids (`kmedoids` 패키지, FasterPAM) | 대여소를 차량별 덩어리로 나누는 단계(step1). 거리뿐 아니라 **수급 균형**도 목적함수에 넣습니다. |
| **군집 목적함수 계수** | `CLUSTER_ALPHA`·`BETA`·`GAMMA` (1·100·3000) | 거리·크기·수급 불균형에 각각 매기는 벌점. **`γ`는 비단조입니다**(γ=2000이 γ=1000보다 나빴습니다) — 두 점 사이를 보간하면 안 됩니다. |
| **ILP** | `step2_optimize/ilp.py` (PuLP + CBC) | 정수계획법. **어느 Pick에서 어느 Drop으로 몇 대를 옮길지**를 정합니다. 군집마다 총 pick = 총 drop이 되도록 맞춥니다. |
| **VRP** | `step2_optimize/vrp.py` | 차량경로문제. **어떤 순서로 돌지**를 정합니다. 지금은 greedy 휴리스틱이고, 최적 대비 평균 9.7%·최악 46.4% 떨어집니다([EXPERIMENTS.md](EXPERIMENTS.md) 6장). |
| **방문 순서** | `order` | 그 회차에서 몇 번째로 들르는지. |
| **적재량** | `load` | 그 시점에 차에 실려 있는 자전거 수(0 ~ 적재 용량). |

## 5. 성과 — 잘했는가

| 말 | 코드 | 뜻 |
| --- | --- | --- |
| **결품 시간** | `stockout_hours` | 그 시간대에 자전거가 0대(또는 만차)라 이용자가 못 쓴 시간의 합. **집행 기준**입니다 — VRP가 실제로 싣고 내린 양으로 계산합니다. |
| **계획 기준 결품** | `stockout_hours_plan` | 계획량이 전부 집행됐다고 가정한 값. 계획과 집행의 격차를 보려고 함께 남깁니다. |
| **개선률** | `improvement_rate` | ⚠️ **"계획 달성률"이지 실제 효과가 아닙니다.** `rebal_qty`가 `target_qty − stock`에서 파생되므로 구조적으로 높게 나옵니다. 대외 인용 시 성격을 밝히십시오([KPI.md](KPI.md)). |
| **커버리지** | `coverage` | 목표 재고가 실제 수요를 덮은 비율. 설계 의도는 95%입니다. |
| **과잉** | over | 덮되 얼마나 넉넉했는가(덮은 경우의 평균 여유 대수). **낭비의 크기**입니다. 비 오는 날의 손실은 결품이 아니라 이쪽으로 나타납니다([WEATHER.md](WEATHER.md) 4-1). |
| **불균형** | imbalance | 목표 재고와 실제 재고의 차이. step4가 재배치 전후로 잽니다. |
| **km당 개선** | — | 이동 1km가 줄인 불균형 대수. **효과와 비용을 함께 보는 지표**입니다 — 개선률만 올리면 소요시간이 늘어납니다. |

## 6. 데이터·저장소

| 말 | 코드 | 뜻 |
| --- | --- | --- |
| **원천 대여이력** | `raw_file`, `rental_history` | 타슈 대여 기록 원본 CSV(약 60만 행/년). |
| **순수요 표** | `net_demand` | (대여소 × 날짜 × 시각) 순수요. `net_00`~`net_23` 컬럼. |
| **재배치 계획** | `rebalance_plan` | 대여소별 `target_qty`·`rebal_qty`. |
| **이동 계획** | `ilp_plan` | ILP가 정한 (출발 대여소 → 도착 대여소 → 대수). |
| **방문 계획** | `vrp_plan` | VRP가 정한 방문 순서·작업 수량. **작업지시서의 원본**입니다. |
| **성과 요약** | `kpi_summary` | 실행 1건 = 1행. 계산 못 한 지표는 NULL로 남습니다. |
| **재고 시계열** | `stock_history` | 평일 09~17시 10분 간격으로 모으는 실측 재고([COLLECTOR.md](COLLECTOR.md)). |
| **재고 스냅샷** | `station_stock` | 파이프라인 실행 시점의 재고 한 장. 위와 **다른 테이블**입니다. |
| **작업지시서** | `webapp/orders.py` | 기사에게 주는 종이. **판정만 하고 계획을 바꾸지 않습니다.** |

## 7. 헷갈리기 쉬운 짝 — 여기서 사고가 납니다

| 이것 | 저것 | 어떻게 다른가 |
| --- | --- | --- |
| **기간**(`period`) | **계획 대상일**(`target_date`) | 전자는 **과거** 수요를 뽑는 달, 후자는 계획을 **집행할** 날. 둘을 헷갈리면 계절 피처가 한 달 어긋납니다. |
| **실행 이름**(`now`) | 실행 시각 | `now`는 **라벨**입니다. 시각을 넣으면 단계 간 파일명이 어긋나고, DB의 `latest_label()`이 사전순 MAX라 순서도 깨집니다. |
| **회차** | **시간대**(`duration`) | 회차는 '나갔다 오는 한 번', 시간대는 그 회차가 겨냥한 5시간 창. 하루 3회차를 돌면 시간대 셋을 각각 계획합니다. |
| **보유 차량 대수** | **회차당 투입 상한** | 앞은 가진 트럭 수, 뒤는 한 번에 낼 수 있는 최대 수(앞의 값으로 잘립니다). 실제 나가는 대수는 **일감**이 정합니다. |
| **계획 기준** | **집행 기준** | 계획량이 다 실행됐다고 보는가, VRP가 실제로 옮긴 양으로 보는가. 계획 기준으로 재면 **무재배치까지 네 방법의 점수가 같아집니다**([TODO.md](TODO.md) 1-2). |
| **개선률** | 실제 효과 | 개선률은 자기가 세운 목표를 얼마나 채웠는지입니다. 효과는 결품 시간으로 재야 합니다. |
| `/api/runs/{id}` | `/api/pipeline-runs` | 앞은 **웹에서 띄운 작업**의 상태, 뒤는 **DB의 실행 이력**. 이름이 비슷하니 주의. |
| `stock_history` | `station_stock` | 앞은 시계열(축 = 시각 × 대여소), 뒤는 실행 1건당 스냅샷 1장. **재고 시계열의 정본은 앞쪽**입니다. |
| **결측** | **0** | 날씨에서 특히 중요합니다 — 강수의 빈칸은 "안 왔다"(0)이고 기온의 빈칸은 진짜 결측입니다. 한 규칙으로 채우면 자료의 89%를 잃습니다. |
| **평일** | **휴일** | 섞지 마십시오. 대여소의 33~37%가 두 구분에서 **부호가 반대**라 섞으면 상쇄돼 작업 대상에서 사라집니다. |
